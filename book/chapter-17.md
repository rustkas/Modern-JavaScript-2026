# Часть V. Производительность

## Глава 17. Современная загрузка: сетевая оркестрация и приоритеты ресурсов

К 2026 году скорость работы веб-приложения определяется не только производительностью JavaScript-кода, но и тем, насколько эффективно приложение управляет загрузкой ресурсов. Браузер способен параллельно выполнять сетевые запросы, разбирать HTML, компилировать JavaScript, вычислять стили и строить интерфейс. Задача разработчика заключается не в ручном управлении этими процессами, а в том, чтобы своевременно сообщить браузеру, какие ресурсы нужны сейчас, какие понадобятся позже и какие можно загрузить только при необходимости.

Современная Web Platform предоставляет для этого набор декларативных механизмов. JavaScript определяет стратегию загрузки, а браузер самостоятельно распределяет сетевые соединения, приоритеты и вычислительные ресурсы.

JavaScript может управлять частью этого процесса непосредственно, но многие решения эффективнее передавать браузеру декларативно через HTML и HTTP.

---

## 17.1. Предварительная загрузка ресурсов: `preload` и `prefetch`

Браузер обнаруживает многие ресурсы только во время разбора HTML или после выполнения JavaScript. Если сообщить о важных файлах заранее, их загрузка начнётся значительно раньше.

### `preload` — загрузка критических ресурсов

`preload` используется для ресурсов, которые необходимы текущей странице. Браузер начинает загрузку сразу после обнаружения такого тега, не ожидая момента, когда ресурс потребуется CSS или JavaScript.

```html
<!-- Шрифты -->
<link rel="preload" href="/fonts/inter.woff2" as="font" crossorigin>

<!-- Изображения первого экрана -->
<link rel="preload" href="/hero-image.webp" as="image">

<!-- Критические таблицы стилей -->
<link rel="preload" href="/critical.css" as="style">

<!-- Критические скрипты -->
<link rel="preload" href="/critical.js" as="script">

<!-- Видео и аудио -->
<link rel="preload" href="/intro.mp4" as="video">
```

**Атрибуты:**

- `as` — тип ресурса (`font`, `image`, `style`, `script`, `video`, `audio`, `fetch`).
- `crossorigin` — требуется для шрифтов и ресурсов с других доменов.
- `type` — MIME-тип для проверки поддержки браузером.

**Пример использования `preload` в JavaScript:**

```javascript
// Создание preload-ссылки динамически
const link = document.createElement('link');
link.rel = 'preload';
link.href = '/api/critical-data.json';
link.as = 'fetch';
link.crossOrigin = 'anonymous';
document.head.appendChild(link);
```

**Когда использовать `preload`:**

- Шрифты, используемые в тексте первого экрана.
- Изображения героя (hero-изображения) над сгибом (above the fold).
- Критические CSS-файлы, блокирующие рендеринг.
- Ключевые JavaScript-файлы для интерактивности.
- API-запросы, необходимые для отображения основного контента.

**Ограничения:** Использовать `preload` следует только для действительно важных ресурсов. Избыточное количество предварительных загрузок создаёт конкуренцию за сетевой канал и может замедлить загрузку страницы. Рекомендуется не более 3-5 preload-ресурсов на страницу.

---

### `prefetch` — подготовка будущих ресурсов

`prefetch` предназначен для ресурсов, которые могут понадобиться позднее (при переходе на другую страницу или после взаимодействия пользователя). Браузер загружает такие файлы только тогда, когда имеются свободные сетевые ресурсы.

```html
<!-- Следующая страница (предполагаемый переход) -->
<link rel="prefetch" href="/dashboard.html">

<!-- Будущий JavaScript-чанк -->
<link rel="prefetch" href="/chunk-editor.js">

<!-- Данные для следующего маршрута SPA -->
<link rel="prefetch" href="/api/next-page-data.json">
```

**Наиболее распространённые сценарии:**

1. **Подготовка следующей страницы** — при наведении на ссылку или скролле к ней.
2. **Загрузка будущих JavaScript-чанков** — для code splitting в SPA.
3. **Подготовка данных следующего маршрута** — предзагрузка API-ответов.

Более конкретный пример:

1. пользователь открывает страницу `/products`;
2. приложение понимает, что следующим вероятным переходом будет `/checkout`;
3. браузеру заранее предлагается загрузить ресурсы, которые могут понадобиться для `/checkout`.

```javascript
// Предзагрузка при наведении на ссылку
linkElement.addEventListener('mouseenter', () => {
  const prefetchLink = document.createElement('link');
  prefetchLink.rel = 'prefetch';
  prefetchLink.href = '/next-page.js';
  document.head.appendChild(prefetchLink);
});
```

Такая стратегия особенно полезна для приложений с разделением кода на маршруты.

При этом `prefetch` остаётся **подсказкой**, а не гарантией загрузки. Браузер учитывает доступную сеть, энергопотребление, текущую нагрузку и собственную стратегию управления ресурсами.


Во многих современных фреймворках (Next.js, Astro, Qwik) `prefetch` автоматически выполняется после появления ссылки в области видимости или после наведения курсора.

## 17.2. `modulepreload`: предварительная загрузка ES-модулей

Для ES Modules существует специализированный механизм предварительной загрузки:

```html
<link rel="modulepreload" href="/app.js">
<link rel="modulepreload" href="/vendor.js">
<link rel="modulepreload" href="/utils.js">
```

браузеру необходимо получить скрипты, определить их статические импорты и загрузить необходимые зависимости.

`modulepreload` позволяет заранее сообщить браузеру о модуле:

```html
<link rel="modulepreload" href="/app.js">
```

**Отличия от обычного `preload`:**

- Браузер знает, что ресурс является модулем JavaScript и может проверить его корректность.
- Модуль загружается и начинается предварительная компиляция до его фактического импорта.
- Сокращается задержка между выполнением `<script type="module" src="/app.js">` и запуском приложения.

```javascript
// Без modulepreload: загрузка → парсинг → компиляция → выполнение
// С modulepreload: загрузка → парсинг → компиляция (заранее) → выполнение
```

**Предварительная загрузка зависимостей:** Спецификация разрешает браузеру автоматически обнаруживать и загружать статические зависимости модуля, однако **не требует этого**. Поэтому одинаковый HTML может вести себя по-разному в разных браузерах. Если необходимо гарантированно избежать каскадной загрузки модулей, каждый важный модуль следует перечислить явно.

**Автоматическое создание modulepreload:**

```javascript
// Vite автоматически создаёт modulepreload-ссылки
// Для каждого чанка в сборке добавляются соответствующие теги
// Это видно в сгенерированном HTML
```

Именно такой подход используют современные сборщики (Vite, Rollup, Webpack), автоматически создавая список всех зависимостей приложения на основе анализа графа модулей.

Если определённый модуль критически важен, его можно указать явно:

```html
<link rel="modulepreload" href="/app.js">
<link rel="modulepreload" href="/vendor.js">
<link rel="modulepreload" href="/charts.js">

<script type="module" src="/app.js"></script>
```

Сборщики и серверные инструменты могут автоматически создавать такие ссылки на основании графа импортов.

Таким образом, `modulepreload` уменьшает задержку загрузки модулей, но не отменяет необходимость правильно проектировать сам граф зависимостей.

## 17.3. Управление сетевыми приоритетами: `fetchpriority`

После того как браузер знает о существовании ресурсов, необходимо определить их относительную важность. Для этого используется атрибут `fetchpriority`.

```html
<!-- Критическое изображение первого экрана -->
<img src="hero.webp" fetchpriority="high">

<!-- Изображение внизу страницы -->
<img src="footer-image.webp" fetchpriority="low">

<!-- Критический CSS через link -->
<link rel="stylesheet" href="/critical.css" fetchpriority="high">
```

**Допустимые значения:**

- `high` — высокий приоритет (критические ресурсы).
- `auto` — приоритет определяется браузером автоматически (значение по умолчанию).
- `low` — низкий приоритет (некритичные ресурсы).

**Использование в JavaScript (`fetch()`):**

```javascript
// Высокий приоритет для API-запроса с данными UI
await fetch('/api/user-profile', { priority: 'high' });

// Низкий приоритет для аналитики
await fetch('/api/analytics', { priority: 'low' });
```

**Важно понимать:** Приоритет представляет собой **рекомендацию**, а не обязательную команду. Браузер самостоятельно принимает окончательное решение, учитывая:

- текущее состояние сети (загруженность канала);
- количество одновременных соединений (лимиты HTTP/2);
- особенности HTTP/2 и HTTP/3 (приоритизация запросов);
- поддержку приоритизации на стороне сервера и CDN;
- загрузку процессора и другие факторы.

Поэтому `fetchpriority` повышает вероятность более ранней загрузки критического ресурса, но не гарантирует её.

## 17.4. Отложенная загрузка ресурсов

Не все данные нужны сразу после открытия страницы. Современная платформа предоставляет два основных механизма ленивой загрузки.

### Нативный Lazy Loading

Изображения и встроенные фреймы могут загружаться автоматически только тогда, когда пользователь приближается к ним.

```html
<!-- Изображение с ленивой загрузкой -->
<img src="photo.webp" loading="lazy" alt="Фото">

<!-- Встроенный фрейм с ленивой загрузкой -->
<iframe src="https://example.com" loading="lazy"></iframe>
```

**Как работает:**

1. Браузер отслеживает положение элемента относительно области просмотра (viewport).
2. Когда элемент приближается к viewport (обычно на расстоянии одного экрана), начинается загрузка.
3. Загрузка происходит автоматически, без участия JavaScript.

**Преимущества:**

- Уменьшает сетевой трафик (не загружаются изображения ниже сгиба).
- Снижает объём используемой памяти.
- Ускоряет время первоначального отображения страницы (LCP, FCP).

**Политика:** По умолчанию браузеры загружают изображения с `loading="lazy"` с задержкой, но не гарантируют конкретное расстояние до области просмотра. Это определяется реализацией браузера.

**Атрибут `decoding="async"` для изображений:**

```html
<img src="photo.webp" decoding="async" loading="lazy">
```

Указывает браузеру декодировать изображение асинхронно, не блокируя рендеринг других элементов.

### Динамический импорт

Код приложения также может загружаться только по мере необходимости.

```javascript
// Загрузка редактора только при открытии диалога
async function openEditor() {
  const { Editor } = await import('./editor.js');
  const editor = new Editor();
  editor.show();
}

// Загрузка модуля при нажатии кнопки
button.addEventListener('click', async () => {
  const chartModule = await import('./chart.js');
  chartModule.renderChart(data);
});
```

**Особенности динамического импорта:**

- Модуль не загружается при открытии страницы.
- Скачивание начинается только в момент выполнения инструкции `import()`.
- Возвращает Promise, который разрешается с объектом модуля.
- Работает во всех современных браузерах и рантаймах.

**Использование в маршрутизации:**

```javascript
// Маршрутизация с ленивой загрузкой
const routes = {
  '/dashboard': () => import('./pages/dashboard.js'),
  '/profile': () => import('./pages/profile.js'),
  '/settings': () => import('./pages/settings.js')
};

async function navigate(path) {
  const loadPage = routes[path];
  if (loadPage) {
    const page = await loadPage();
    page.render();
  }
}
```

Динамический импорт лежит в основе:

- **Code Splitting** — разделение кода на чанки.
- **Ленивой загрузки маршрутов** — каждый маршрут загружается отдельно.
- **Подключения тяжёлых редакторов** — загрузка только при необходимости.
- **Загрузки графических библиотек** — например, Three.js загружается только при открытии 3D-сцены.
- **Подключения модулей машинного обучения** — загрузка модели только при активации AI-функции.

**Динамический импорт с предзагрузкой:**

```javascript
// Наведение на кнопку → начало загрузки модуля
button.addEventListener('mouseenter', () => {
  import('./heavy-module.js'); // Начинает загрузку без ожидания
});

button.addEventListener('click', async () => {
  const module = await import('./heavy-module.js');
  module.init();
});
```

## 17.5. Стратегия современной загрузки

Эффективная загрузка строится как последовательность взаимодополняющих механизмов:

1. **`preload`** сообщает браузеру о критически важных ресурсах текущей страницы (шрифты, изображения первого экрана, критические CSS/JS).

2. **`modulepreload`** заранее загружает и компилирует JavaScript-модули, сокращая задержку выполнения.

3. **`fetchpriority`** помогает браузеру распределить сетевые приоритеты между ресурсами.

4. **`prefetch`** подготавливает ресурсы, которые могут понадобиться при следующем действии пользователя (наведение, клик, переход).

5. **`loading="lazy"`** и **динамический `import()`** откладывают загрузку всего, что не требуется немедленно (изображения ниже сгиба, некритичные модули).

**Пример комплексной стратегии:**

```html
<!-- 1. Критические ресурсы текущей страницы -->
<link rel="preload" href="/fonts/roboto.woff2" as="font" crossorigin>
<link rel="preload" href="/hero.jpg" as="image" fetchpriority="high">
<link rel="modulepreload" href="/app.js">

<!-- 2. Ресурсы для следующего действия -->
<link rel="prefetch" href="/dashboard.js" as="script">

<!-- 3. Ленивая загрузка -->
<img src="gallery-photo.webp" loading="lazy" decoding="async">
```

**Когда что использовать:**

| Сценарий | Механизм |
| -------- | -------- |
| Критический ресурс для первого экрана | `preload` + `fetchpriority="high"` |
| Основной JavaScript-модуль приложения | `modulepreload` |
| Ресурс, который понадобится на следующей странице | `prefetch` |
| Изображение за пределами видимой области | `loading="lazy"` |
| Модуль, который используется не всегда | Динамический `import()` |
| Фоновый API-запрос (аналитика) | `fetch()` с `priority: 'low'` |

Такой подход позволяет сократить время до появления первого содержимого (FCP, LCP), ускорить интерактивность приложения (TTI) и уменьшить объём одновременно загружаемых данных.

## Заключение главы

Современная Web Platform самостоятельно выполняет сетевые запросы, распределяет пропускную способность канала, компилирует модули и управляет очередями загрузки. JavaScript больше не занимается низкоуровневым управлением сетью. Его задача — описать стратегию работы приложения с помощью декларативных механизмов платформы.

`preload` загружает критически важные ресурсы текущей страницы до того, как они потребуются. `modulepreload` заранее загружает и компилирует ES-модули, сокращая задержку выполнения. `fetchpriority` помогает браузеру распределить приоритеты между ресурсами (high, auto, low). `prefetch` подготавливает ресурсы для будущих действий пользователя. `loading="lazy"` откладывает загрузку изображений и фреймов до приближения к области просмотра. Динамический `import()` позволяет загружать JavaScript-модули по требованию.

Понимание назначения `preload`, `prefetch`, `modulepreload`, `fetchpriority`, `loading="lazy"` и динамического `import()` позволяет строить приложения, которые начинают работать быстрее, эффективнее используют сетевые ресурсы и остаются отзывчивыми даже при медленном соединении.
