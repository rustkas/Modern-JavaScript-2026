# Часть IV. Современная работа с данными

# Глава 12. Работа с данными: JSON, Structured Clone и передача памяти

JavaScript всегда был языком обмена данными. Если в первые годы развития веба основной задачей было преобразование объектов в JSON и обратно, то к 2026 году область работы с данными значительно расширилась. Современные приложения постоянно передают информацию между потоками выполнения, веб-воркерами, браузером, сервером, локальными базами данных и модулями WebAssembly.

Поэтому современный JavaScript использует сразу несколько механизмов, каждый из которых решает собственную задачу:

- **JSON** — обмен данными между различными системами (сеть, API, конфигурация).
- **Structured Clone** — безопасное копирование сложных структур данных внутри одной среды выполнения.
- **Transferable Objects** — передача владения памятью без копирования между потоками.
- **Import Attributes** — подключение статических данных как модулей в граф зависимостей.

Понимание различий между этими механизмами позволяет выбирать правильный инструмент для каждой архитектурной задачи.

## 12.1. JSON — универсальный язык обмена данными

Несмотря на появление новых механизмов передачи данных, JSON остаётся главным форматом взаимодействия между приложениями.

Объект `JSON` предоставляет два стандартных метода:

- `JSON.parse(text)` — преобразует JSON-строку в объекты JavaScript.
- `JSON.stringify(value)` — сериализует объекты JavaScript в JSON-строку.

```javascript
// Сериализация
const obj = { name: 'Alice', age: 30, active: true };
const json = JSON.stringify(obj);
// '{"name":"Alice","age":30,"active":true}'

// Десериализация
const parsed = JSON.parse(json);
// { name: 'Alice', age: 30, active: true }
```

JSON является текстовым форматом и поддерживает только ограниченный набор типов данных:

- строки;
- числа (целые и с плавающей точкой);
- логические значения (`true`, `false`);
- `null`;
- объекты (с ключами-строками);
- массивы.

JSON не поддерживает:

- функции — они удаляются при сериализации;
- `Map` и `Set` — они преобразуются в пустые объекты или массивы без сохранения структуры;
- `WeakMap` и `WeakSet` — не поддерживаются;
- `Symbol` — игнорируется при сериализации;
- `BigInt` — вызывает ошибку `TypeError` при сериализации;
- циклические ссылки — вызывают ошибку `TypeError: Converting circular structure to JSON`.

```javascript
const circular = { name: 'Alice' };
circular.self = circular;
JSON.stringify(circular); // TypeError: Converting circular structure to JSON
```

Поэтому JSON следует рассматривать исключительно как формат обмена данными между различными системами, а не как механизм глубокого копирования объектов.

## 12.2. JSON-модули и Import Attributes

Современная система ES Modules позволяет импортировать JSON напрямую без предварительной загрузки через `fetch()`.

```javascript
import config from "./config.json" with { type: "json" };

console.log(config.apiUrl);
console.log(config.timeout);
```

Такой импорт обладает рядом особенностей:

**1. Единственный экспорт.** JSON-модуль экспортирует только одно значение — `default export`. Невозможно использовать именованные импорты из JSON-файла.

```javascript
import { apiUrl } from "./config.json" with { type: "json" }; // ❌ Ошибка
```

**2. MIME-тип.** Сервер обязан вернуть файл с MIME-типом `application/json`. Иначе браузер отклонит загрузку модуля с ошибкой.

**3. Синтаксис.** Современный синтаксис использует конструкцию `with { type: "json" }`, стандартизированную в рамках **ES2025**. Ранее использовался синтаксис `assert { type: "json" }` — здесь важно уточнить масштаб изменений: это не просто менее предпочтительный вариант, а синтаксис, который был официально исключён из спецификации TC39 (переход от «чистой проверки» к возможности влиять на загрузку модуля потребовал смены семантики, а не только ключевого слова). Практические последствия различаются по средам: Chrome полностью удалил поддержку `assert` начиная с версии V8 12.6 — попытка использовать этот синтаксис вызывает `SyntaxError`, а не предупреждение. Firefox и Safari синтаксис `assert` никогда не реализовывали вовсе, сразу перейдя к `with`. Поэтому в 2026 году любой код с `assert { type: "json" }` стоит рассматривать не как «устаревший, но рабочий», а как ошибку, требующую немедленного исправления.

```javascript
// Удалённый из спецификации синтаксис — вызывает SyntaxError в актуальных версиях Chrome
import config from "./config.json" assert { type: "json" };

// Единственный поддерживаемый синтаксис
import config from "./config.json" with { type: "json" };
```

**4. Статический анализ.** Использование JSON-модулей позволяет браузеру заранее построить граф зависимостей приложения и загрузить необходимые данные ещё до начала выполнения программы.

JSON-модули особенно полезны для:

- конфигурационных файлов приложения;
- данных локализации (переводы);
- статических списков (страны, города, категории);
- файлов с настройками.

## 12.3. Сериализация через JSON

Метод `JSON.stringify()` создаёт текстовое представление объекта. Во время сериализации происходят важные преобразования.

**Удаление функций и undefined.** Функции и свойства типа `undefined` удаляются из результата.

```javascript
const obj = {
  x: 1,
  f() { return 2; },
  y: undefined,
  z: null
};
JSON.stringify(obj); // '{"x":1,"z":null}'
```

**Преобразование Date.** Объекты `Date` автоматически преобразуются в строку ISO 8601.

```javascript
const obj = { created: new Date('2026-08-01T08:30:00Z') };
JSON.stringify(obj);
// '{"created":"2026-08-01T08:30:00.000Z"}'
```

**Циклические ссылки.** При наличии циклических ссылок сериализация завершается ошибкой.

```javascript
const obj = { name: 'Alice' };
obj.self = obj;
JSON.stringify(obj); // TypeError: Converting circular structure to JSON
```

**Параметры сериализации:**

```javascript
// Замена значений через replacer (функция или массив ключей)
JSON.stringify(obj, (key, value) => {
  if (key === 'password') return undefined; // Исключить password
  return value;
}, 2); // Отступ 2 пробела (pretty print)

// Массив ключей для включения
JSON.stringify(obj, ['name', 'age']); // Только поля name и age
```

**Метод `toJSON()`.** Если необходимо изменить процесс сериализации, класс может определить метод `toJSON()`, который возвращает представление объекта, используемое при вызове `JSON.stringify()`.

```javascript
class User {
  constructor(name, password) {
    this.name = name;
    this.password = password;
  }
  
  toJSON() {
    // Исключаем пароль из сериализации
    return { name: this.name };
  }
}

const user = new User('Alice', 'secret123');
JSON.stringify(user); // '{"name":"Alice"}'
```

## 12.4. Structured Clone — глубокое копирование данных

Современный JavaScript предоставляет встроенный алгоритм глубокого копирования через глобальную функцию `structuredClone()`.

```javascript
const original = {
  name: 'Alice',
  age: 30,
  hobbies: ['reading', 'swimming'],
  preferences: new Map([['theme', 'dark'], ['language', 'en']]),
  createdAt: new Date()
};

const clone = structuredClone(original);

// clone — полностью независимая копия
clone.hobbies.push('gaming');
console.log(original.hobbies); // ['reading', 'swimming'] — не изменился
```

В отличие от JSON, этот алгоритм сохраняет структуру объекта практически полностью.

**Что поддерживается:**

- массивы и вложенные объекты любой глубины;
- циклические ссылки — алгоритм корректно обрабатывает их, создавая точную копию структуры;

```javascript
const obj = { name: 'Alice' };
obj.self = obj;
const clone = structuredClone(obj);
console.log(clone.self === clone); // true — циклическая ссылка сохранена
```

- `Map` и `Set` — копируются со всеми значениями;
- `Date` — копируется с сохранением времени;
- `RegExp` — копируется с паттерном и флагами, но с одной практически важной оговоркой: свойство `lastIndex` (позиция, с которой продолжится следующий поиск при глобальном флаге `g`) **не сохраняется** и сбрасывается в клоне на 0, даже если в оригинале поиск был в процессе;

```javascript
const original = /a/g;
original.exec('aaa'); // lastIndex становится 1
const clone = structuredClone(original);
console.log(clone.lastIndex); // 0 — сброшен, несмотря на то что паттерн и флаги сохранены
```

- `Blob` и `File` — копируются как объекты;
- `ArrayBuffer` и типизированные массивы — копируются полностью.

Главное отличие состоит в том, что алгоритм работает непосредственно с внутренним представлением объектов, а не через промежуточную текстовую форму (как JSON). Это делает его более быстрым для сложных структур и позволяет сохранять типы данных, не поддерживаемые JSON.

## 12.5. Ограничения Structured Clone

Несмотря на широкие возможности, `structuredClone()` копирует только данные. Он не переносит поведение объектов.

**Экземпляры классов.** Экземпляр пользовательского класса после клонирования перестаёт быть экземпляром этого класса.

```javascript
class User {
  constructor(name) {
    this.name = name;
  }
  greet() {
    console.log(`Hello, ${this.name}`);
  }
}

const user = new User('Alice');
const clone = structuredClone(user);

console.log(clone instanceof User); // false
console.log(clone.greet); // undefined
// clone — это обычный объект { name: 'Alice' }, без методов
```

**Что не поддерживается:**

- функции — любая функция вызывает `DataCloneError`;
- DOM-узлы (`Element`, `Document`, `Node`) — вызывают `DataCloneError`;
- объекты, содержащие внутренние ссылки на конкретную среду выполнения (например, `window`, `Worker`, `WebSocket`);
- `Symbol` — не поддерживается;
- `WeakMap` и `WeakSet` — не поддерживаются.

```javascript
const withFunction = { name: 'Alice', greet: () => 'Hello' };
structuredClone(withFunction); // DataCloneError: function objects cannot be cloned

const withDOM = { element: document.createElement('div') };
structuredClone(withDOM); // DataCloneError: HTMLElement objects cannot be cloned
```

Поэтому `structuredClone()` следует использовать для передачи данных, а не объектов с бизнес-логикой. Если необходимо клонировать объекты с методами, следует реализовать собственную стратегию клонирования.

## 12.6. Transferable Objects — передача памяти без копирования

При работе с большими объёмами данных даже глубокое копирование становится слишком дорогой операцией. Для таких случаев используется механизм Transferable Objects.

**Как это работает:** Вместо создания копии память просто передаётся новому владельцу. Исходный владелец теряет доступ к данным. Передача происходит практически мгновенно независимо от размера данных.

Наиболее распространённый пример — передача `ArrayBuffer` в Web Worker:

```javascript
// Основной поток
const buffer = new ArrayBuffer(1024 * 1024 * 100); // 100 МБ
const view = new Uint8Array(buffer);

// Заполняем данные
for (let i = 0; i < view.length; i++) {
  view[i] = i % 256;
}

// Передаём буфер в Worker
worker.postMessage({ data: buffer }, [buffer]);

// После передачи основной поток теряет доступ к буферу
console.log(buffer.byteLength); // 0 — буфер передан
```

В Worker'ере:

```javascript
// worker.js
self.onmessage = (event) => {
  const buffer = event.data.data; // Получаем буфер
  const view = new Uint8Array(buffer);
  // Работаем с данными
  console.log(view.length); // 104857600 — 100 МБ
};
```

**Что можно передавать через Transferable Objects:**

- `ArrayBuffer` — самый распространённый тип.
- `MessagePort` — порт для обмена сообщениями.
- `ReadableStream` — поток для чтения данных.
- `WritableStream` — поток для записи данных.
- `TransformStream` — поток для преобразования данных.
- `OffscreenCanvas` — канвас, отображаемый вне основного потока.

**Важно:** Передача происходит только в момент вызова `postMessage()`. Объект, однажды переданный, становится недоступен в исходном потоке. Это принципиальное отличие от копирования — память не дублируется, а передаётся.

Такой подход широко используется при обработке:

- изображений — передача больших битмапов в Worker для обработки;
- видео — передача кадров для кодирования/декодирования;
- аудио — передача звуковых буферов для анализа;
- машинного обучения — передача тензоров в WebAssembly или Worker;
- WebAssembly — передача памяти между модулями;
- трёхмерной графики — передача буферов в WebGL/WebGPU.

## 12.7. Когда использовать каждый механизм

Современный JavaScript предлагает несколько способов работы с данными, каждый из которых предназначен для своей задачи.

| Задача | Инструмент | Пример использования |
| ------ | ---------- | -------------------- |
| Передача данных по сети | JSON | REST API, WebSocket, Server-Sent Events |
| Загрузка конфигурации приложения | JSON Modules | `import config from "./config.json" with { type: "json" }` |
| Глубокое копирование объектов внутри приложения | `structuredClone()` | Копирование состояния до изменения, реактивные системы |
| Передача больших массивов между потоками | Transferable Objects | Передача изображений, видео, аудио в Web Workers |
| Копирование объектов с методами и состоянием | Собственная сериализация | `toJSON()` и кастомные методы клонирования |

**Практические рекомендации:**

1. **Используйте JSON только для обмена данными между системами** (браузер ↔ сервер). Для внутреннего копирования используйте `structuredClone()`.

2. **Используйте JSON-модули для статических данных**, которые должны быть доступны на этапе загрузки приложения. Это позволяет браузеру оптимизировать загрузку.

3. **Используйте `structuredClone()` для копирования сложных структур данных** внутри приложения. Это безопаснее и быстрее, чем `JSON.parse(JSON.stringify())`.

4. **Используйте Transferable Objects для передачи больших объёмов данных между потоками.** Это единственный способ избежать копирования памяти.

5. **Для копирования объектов с бизнес-логикой реализуйте собственные методы сериализации.** `structuredClone()` не переносит методы и прототипы.

Правильный выбор механизма позволяет избежать лишнего копирования памяти, уменьшить потребление ресурсов и повысить производительность приложения.

## Заключение главы

Современный JavaScript использует несколько взаимодополняющих механизмов работы с данными. **JSON** остаётся универсальным форматом обмена между различными системами — он текстовый, человекочитаемый и поддерживается всеми языками программирования. **JSON-модули** позволяют включать статические данные непосредственно в граф зависимостей ES Modules, что упрощает загрузку и оптимизацию. **`structuredClone()`** обеспечивает безопасное глубокое копирование сложных структур данных, включая `Map`, `Set`, `Date` и циклические ссылки. **Transferable Objects** позволяют передавать большие объёмы памяти между потоками практически без затрат времени, что критично для высокопроизводительных приложений — обработки изображений, видео, машинного обучения и WebAssembly.

Главное правило современной разработки состоит в том, чтобы выбирать инструмент в соответствии с задачей. JSON предназначен для обмена данными между приложениями, `structuredClone()` — для копирования структур данных внутри среды выполнения, а Transferable Objects — для максимально эффективной передачи памяти между потоками исполнения. Понимание различий между этими механизмами позволяет писать более эффективный, безопасный и поддерживаемый код. Такое разделение делает код быстрее, проще и лучше соответствует архитектуре современной Web Platform.
