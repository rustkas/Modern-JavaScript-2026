# Часть III. Работа с браузером

# Глава 11. Современные Browser APIs: JavaScript как интерфейс к возможностям Web Platform

Современный JavaScript уже давно перестал быть языком, ограниченным работой с DOM и обработкой пользовательских событий. Основная тенденция последних лет заключается в том, что всё больше возможностей операционной системы, оборудования и браузерной среды становятся доступны через стандартизированные API Web Platform.

При этом важно понимать разделение ответственности. ECMAScript определяет синтаксис, типы данных и механизм выполнения языка, тогда как доступ к файлам, сети, экрану, буферу обмена, датчикам устройств, потокам данных и другим возможностям предоставляет браузер. JavaScript лишь связывает эти интерфейсы в единую программу.

Именно поэтому современный JavaScript всё чаще называют **декларативным интерфейсом к Web Platform**: язык не реализует самостоятельно работу с оборудованием, а управляет специализированными системными подсистемами браузера.

---

## 11.1. Browser APIs как расширение языка

Все современные браузеры предоставляют JavaScript сотни стандартизированных API, которые превращают веб-приложение в полноценное программное обеспечение.

Наиболее важные группы Browser API включают:

- **Работу с документом и интерфейсом** — DOM (управление структурой документа), CSSOM (работа со стилями), Web Components (создание кастомных элементов).
- **Сетевые технологии** — `fetch` (HTTP-запросы), WebSocket (двунаправленная связь), WebTransport (низкоуровневая передача данных), WebRTC (реальное время, видео и аудио).
- **Хранение данных** — Storage API (`localStorage`, `sessionStorage`), IndexedDB (документо-ориентированная база данных), Cache Storage (кеширование для Service Workers).
- **Графику** — Canvas (2D-графика), SVG (векторная графика), WebGL (3D-графика), WebGPU (высокопроизводительная 3D-графика следующего поколения).
- **Мультимедиа** — MediaDevices (камера и микрофон), Web Audio (обработка звука), WebCodecs (кодирование/декодирование видео и аудио).
- **Файловую систему** — File API (чтение файлов), File System Access API (глубокий доступ к файловой системе).
- **Аппаратные возможности устройства** — датчики (акселерометр, гироскоп), геолокация, батарея, вибрация.
- **Фоновые вычисления** — Web Workers (фоновые потоки), Service Workers (прокси между приложением и сетью).
- **Безопасность и криптографию** — Web Crypto API (криптографические операции), Permissions API (управление разрешениями).

Все эти возможности доступны через единый язык JavaScript и используют одинаковые принципы работы:

- объекты — API представляются через JavaScript-объекты с методами и свойствами;
- события — асинхронные уведомления через модель событий;
- промисы — асинхронные операции возвращают Promise;
- асинхронные операции — `async/await` для работы с промисами;
- `AbortSignal` — отмена операций через `AbortController`;
- Web Streams — потоковая обработка данных.

Благодаря этому изучение одного API значительно упрощает освоение остальных. Например, механизм работы с `AbortSignal` одинаков для Fetch API, чтения файлов и обработчиков событий.

## 11.2. Интеграция с операционной системой

Современные браузеры способны взаимодействовать с операционной системой значительно глубже, чем это было возможно несколько лет назад.

### Clipboard API

Clipboard API предоставляет безопасный асинхронный доступ к системному буферу обмена. JavaScript может читать текст, записывать текст, работать с изображениями и обмениваться несколькими типами данных одновременно.

```javascript
// Запись текста в буфер обмена
await navigator.clipboard.writeText('Hello, World!');

// Чтение текста из буфера обмена
const text = await navigator.clipboard.readText();

// Запись изображения в буфер обмена
const imageBlob = await fetch('image.png').then(r => r.blob());
await navigator.clipboard.write([
  new ClipboardItem({
    'image/png': imageBlob
  })
]);

// Чтение изображения из буфера обмена
const clipboardItems = await navigator.clipboard.read();
for (const item of clipboardItems) {
  if (item.types.includes('image/png')) {
    const blob = await item.getType('image/png');
    // Обработка изображения
  }
}
```

Все операции требуют безопасного контекста (HTTPS) и подчиняются политике разрешений браузера. Браузер запрашивает разрешение пользователя при первом доступе к буферу обмена.

---

### Web Share API

Web Share API позволяет открыть стандартное окно операционной системы для отправки данных в другие приложения. Приложение передаёт браузеру объект с данными: заголовок, текст, URL и файлы.

```javascript
// Проверка возможности отправки
if (navigator.canShare) {
  const shareData = {
    title: 'Заголовок',
    text: 'Текст для отправки',
    url: 'https://example.com'
  };

  if (navigator.canShare(shareData)) {
    await navigator.share(shareData);
  }
}

// Отправка с файлами
const file = new File(['содержимое'], 'file.txt', { type: 'text/plain' });
await navigator.share({
  title: 'Файл',
  files: [file]
});
```

Браузер самостоятельно отображает привычный пользователю интерфейс обмена. Здесь важна оговорка о зрелости технологии: Web Share API поддерживается в Chrome, Edge и Safari (включая десктопные версии), но **не реализован в десктопном Firefox**, из-за чего формально не входит в Baseline — MDN явно отмечает это ограничение. На практике это значит, что API стоит применять как прогрессивное улучшение с проверкой доступности (`if (navigator.canShare)` в примере выше), а не как единственный способ поделиться контентом.

---

### Fullscreen API

Fullscreen API позволяет перевести отдельный элемент страницы в полноэкранный режим. Это используется в видеоплеерах, редакторах, презентациях и игровых приложениях.

```javascript
const element = document.getElementById('video-player');

// Вход в полноэкранный режим
await element.requestFullscreen();

// Выход из полноэкранного режима
await document.exitFullscreen();

// Проверка полноэкранного режима
document.fullscreenElement !== null; // true если в полноэкранном режиме

// События
document.addEventListener('fullscreenchange', () => {
  console.log('Режим изменился');
});
```

Полноэкранный режим всегда требует явного действия пользователя (например, клика) и не может быть активирован произвольно из соображений безопасности. Стоит также иметь в виду, что на iOS Safari эта технология исторически была одним из наиболее ограниченных API — полноценная реализация для веб-приложений (не только видео) в Safari на iOS появилась значительно позже, чем в остальных браузерах, поэтому для мобильных сценариев стоит отдельно проверять актуальный статус для целевых версий iOS.

---

### Screen Wake Lock API

Во многих приложениях недопустимо автоматическое отключение дисплея. Screen Wake Lock API позволяет временно запретить переход экрана в спящий режим.

```javascript
// Запрос блокировки
const wakeLock = await navigator.wakeLock.request('screen');

// Освобождение блокировки
wakeLock.release();

// Отслеживание состояния
wakeLock.addEventListener('release', () => {
  console.log('Блокировка освобождена');
});
```

Технология достигла статуса Baseline Newly Available в мае 2024 года — она реализована во всех трёх основных движках, включая Safari с версии 16.4. Типичные сценарии использования: навигация, электронные книги, презентации, видеоконференции, онлайн-обучение. После завершения работы блокировка должна быть освобождена приложением, чтобы экономить заряд батареи.

## 11.3. Современное хранение данных

Web Platform предоставляет несколько механизмов хранения данных, предназначенных для различных задач.

### Web Storage

`localStorage` и `sessionStorage` подходят для хранения небольших объёмов данных (до 5-10 МБ). Их преимущества: простота, синхронный интерфейс, высокая совместимость.

```javascript
// Установка значения
localStorage.setItem('key', 'value');
sessionStorage.setItem('temp', 'данные на сессию');

// Получение значения
const value = localStorage.getItem('key');

// Удаление
localStorage.removeItem('key');
localStorage.clear();
```

Однако эти API не предназначены для хранения больших объёмов информации. Все данные хранятся в виде строк, что требует сериализации для объектов.

---

### IndexedDB

Для большинства современных приложений основной клиентской базой данных является IndexedDB. Она обеспечивает хранение миллионов записей, индексацию для быстрого поиска, транзакции для целостности данных, асинхронную работу (не блокирует главный поток) и структурированное клонирование объектов (сохраняет сложные структуры данных).

```javascript
// Открытие базы данных
const request = indexedDB.open('MyDatabase', 1);

request.onupgradeneeded = (event) => {
  const db = event.target.result;
  const store = db.createObjectStore('users', { keyPath: 'id' });
  store.createIndex('email', 'email', { unique: true });
};

request.onsuccess = (event) => {
  const db = event.target.result;
  // Добавление записи
  const transaction = db.transaction('users', 'readwrite');
  const store = transaction.objectStore('users');
  store.add({ id: 1, name: 'Alice', email: 'alice@example.com' });
  
  // Поиск по индексу
  const index = store.index('email');
  const getRequest = index.get('alice@example.com');
};
```

Практически все крупные Progressive Web Apps (PWA) используют IndexedDB как основное локальное хранилище для работы в офлайн-режиме.

---

### Storage API

Storage API предоставляет информацию о доступном дисковом пространстве.

```javascript
// Получение информации о хранилище
const estimate = await navigator.storage.estimate();
console.log(`Использовано: ${estimate.usage} байт`);
console.log(`Доступно: ${estimate.quota} байт`);

// Запрос сохранения данных (предотвращает автоматическую очистку)
const persisted = await navigator.storage.persisted();
if (!persisted) {
  await navigator.storage.persist();
}
```

Следует учитывать, что политика очистки данных различается между браузерами. Особенно заметны различия в Safari, где удаление редко используемых данных происходит значительно агрессивнее. Запрос сохранения (`persist()`) помогает браузеру понять, что данные важны, но не гарантирует их сохранность.

## 11.4. Работа с файлами

Работа с пользовательскими файлами остаётся одной из наиболее быстро развивающихся областей Web Platform.

### File API

Во всех современных браузерах поддерживается классическая работа с файлами: выбор файлов через `<input type="file">`, чтение содержимого, загрузка файлов на сервер через Fetch, создание Blob и генерация файлов для скачивания.

```javascript
// Выбор файлов
const input = document.createElement('input');
input.type = 'file';
input.multiple = true;

input.addEventListener('change', async (event) => {
  const files = event.target.files;
  for (const file of files) {
    console.log('Имя:', file.name);
    console.log('Размер:', file.size);
    console.log('Тип:', file.type);
    
    // Чтение содержимого
    const reader = new FileReader();
    reader.onload = (e) => {
      console.log('Содержимое:', e.target.result);
    };
    reader.readAsText(file);
  }
});

// Создание и скачивание файла
const blob = new Blob(['Hello, World!'], { type: 'text/plain' });
const url = URL.createObjectURL(blob);
const link = document.createElement('a');
link.href = url;
link.download = 'hello.txt';
link.click();
URL.revokeObjectURL(url);
```

Этот механизм полностью кросс-браузерен и работает во всех современных браузерах.

---

### File System Access API

File System Access API предоставляет значительно более глубокую интеграцию с файловой системой. Он позволяет открывать существующие файлы и сохранять изменения, работать с каталогами, повторно использовать разрешения пользователя (браузер запоминает выданные разрешения).

```javascript
// Открытие файла
const fileHandle = await window.showOpenFilePicker({
  types: [{
    description: 'Текстовые файлы',
    accept: { 'text/plain': ['.txt'] }
  }],
  multiple: false
});

// Чтение файла
const file = await fileHandle[0].getFile();
const contents = await file.text();

// Сохранение изменений
const writable = await fileHandle[0].createWritable();
await writable.write('Новое содержимое');
await writable.close();

// Открытие папки
const dirHandle = await window.showDirectoryPicker();
const entries = [];
for await (const entry of dirHandle.values()) {
  entries.push(entry);
}
```

Однако необходимо учитывать статус стандарта. Полноценная поддержка File System Access API существует только в браузерах семейства Chromium (Chrome, Edge, Opera). Firefox и Safari не поддерживают методы `showOpenFilePicker()`, `showSaveFilePicker()` и `showDirectoryPicker()`. Поэтому приложения, использующие этот API, должны предусматривать альтернативный сценарий работы через обычный выбор файлов через `<input type="file">`.

## 11.5. Взаимодействие между вкладками и потоками выполнения

Современные веб-приложения редко ограничиваются одной вкладкой браузера. Для обмена информацией между несколькими экземплярами приложения используются специальные API.

### BroadcastChannel

BroadcastChannel обеспечивает обмен сообщениями между всеми вкладками одного происхождения (Origin).

```javascript
// Создание канала
const channel = new BroadcastChannel('app-updates');

// Отправка сообщения
channel.postMessage({ type: 'USER_LOGGED_OUT', userId: 42 });

// Получение сообщения
channel.addEventListener('message', (event) => {
  console.log('Получено:', event.data);
  if (event.data.type === 'USER_LOGGED_OUT') {
    // Выход из аккаунта во всех вкладках
    logout();
  }
});

// Закрытие канала
channel.close();
```

BroadcastChannel удобно использовать для синхронизации состояния (например, выход пользователя из аккаунта во всех вкладках), обновления настроек (изменение темы или языка), передачи уведомлений между вкладками.

---

### Web Locks API

Если несколько вкладок одновременно работают с одним ресурсом, возникает риск состояния гонки. Web Locks API предоставляет механизм взаимного исключения.

```javascript
// Запрос блокировки
await navigator.locks.request('sync-resource', async (lock) => {
  // Критическая секция
  // Только один экземпляр приложения может выполнять этот код
  await synchronizeData();
});

// Проверка наличия блокировки
const lock = await navigator.locks.query();
console.log('Активные блокировки:', lock.held);
```

С его помощью можно гарантировать, что определённая операция выполняется только одним экземпляром приложения. Это особенно полезно при работе с IndexedDB (предотвращение конфликтов записи), синхронизацией данных (только один экземпляр синхронизирует с сервером), фоновыми задачами (только один экземпляр выполняет задачу), Service Worker (координация обновлений).

## 11.6. Производительность и архитектура современных API

Большинство новых Browser API разрабатываются по единым архитектурным принципам.

Современный API обычно обладает следующими свойствами:

- **Асинхронный интерфейс на основе Promise** — все операции, которые могут занять время, возвращают Promise и не блокируют главный поток.
- **Поддержка `AbortSignal`** — возможность отмены операций через `AbortController`, что позволяет управлять жизненным циклом.
- **Безопасная работа только по HTTPS** — большинство современных API требуют безопасного контекста для защиты данных.
- **Встроенная система разрешений пользователя** — доступ к чувствительным функциям (геолокация, камера, микрофон) требует явного согласия пользователя.
- **Интеграция с EventTarget** — события для уведомлений об изменениях состояния.
- **Возможность использования совместно с Web Workers** — API могут работать в фоновых потоках.
- **Единая модель обработки ошибок через исключения** — ошибки выбрасываются как исключения или возвращаются через отклонённые Promise.

Благодаря этому новые API имеют предсказуемое поведение и легко комбинируются между собой.

Например, один и тот же `AbortSignal` может одновременно управлять сетевым запросом (`fetch`), чтением файла, обработчиком события и потоком данных:

```javascript
const controller = new AbortController();
const signal = controller.signal;

// Все операции отменяются одним вызовом
const response = await fetch('/api/data', { signal });
const file = await readFile(signal);
element.addEventListener('click', handler, { signal });

// Отмена всех операций
controller.abort();
```

Такой подход существенно упрощает управление жизненным циклом приложения и предотвращает утечки памяти.

## 11.7. Унификация Web Platform

Одной из важнейших тенденций последних лет стала постепенная унификация браузерных и серверных сред выполнения.

Здесь стоит уточнить организационный статус ключевой инициативы этого процесса — **WinterTC**. Изначально работа велась в открытой рабочей группе W3C — **WinterCG** (Web-interoperable Runtimes Community Group), — но в январе 2025 года эта группа была закрыта, а её работа передана в **Ecma International**, тот же орган, что стандартизирует через TC39 сам язык. Актуальное официальное название инициативы — **Ecma TC55**, неформально по-прежнему именуемое **WinterTC**. Именно эта инициатива способствует тому, чтобы такие API, как `fetch`, URL API, Web Streams, Encoding API, AbortController и другие, работали одинаково в браузерах, Node.js, Deno и Bun. Это позволяет использовать один и тот же код в разных средах без изменений.

При этом многие Browser API по своей природе остаются привязанными к браузеру, поскольку требуют взаимодействия с пользователем или оборудования устройства. К ним относятся:

- Clipboard API — доступ к буферу обмена.
- Fullscreen API — полноэкранный режим.
- Screen Wake Lock API — блокировка экрана.
- File System Access API — глубокий доступ к файловой системе.
- Мультимедийные интерфейсы — камера, микрофон, аудио, видео.
- Датчики устройства — геолокация, акселерометр, гироскоп.

Эти API не могут быть реализованы на сервере, поскольку требуют аппаратного обеспечения и взаимодействия с пользователем.

Таким образом, современный JavaScript представляет собой единый язык программирования, а Web Platform — универсальную среду выполнения, которая предоставляет доступ к возможностям браузера и операционной системы через стандартизированные API. Это позволяет разработчикам использовать один язык для всех типов приложений, сохраняя при этом переносимость и безопасность.

## Заключение главы

Browser API стали неотъемлемой частью современного JavaScript. Именно они позволяют веб-приложениям работать с файлами, локальными базами данных, буфером обмена, экраном, сетью и другими ресурсами устройства. Clipboard API обеспечивает безопасный доступ к буферу обмена. Web Share API интегрирует приложение с системным интерфейсом обмена. Fullscreen API и Screen Wake Lock API управляют отображением и энергопотреблением. Web Storage, IndexedDB и Storage API предоставляют различные уровни хранения данных. File API и File System Access API обеспечивают работу с файлами — от простого чтения до глубокой интеграции с файловой системой. BroadcastChannel и Web Locks API координируют работу между вкладками и предотвращают конфликты.

Главная тенденция 2026 года заключается в том, что JavaScript всё меньше занимается непосредственной реализацией сложных системных механизмов и всё чаще выступает координатором возможностей Web Platform. Язык определяет логику приложения, а браузер предоставляет высокопроизводительные, безопасные и стандартизированные сервисы для взаимодействия с пользователем, операционной системой и аппаратным обеспечением. Современные API используют единые архитектурные принципы — Promise, AbortSignal, события, систему разрешений — что делает их предсказуемыми и легко комбинируемыми. Унификация браузерных и серверных сред через WinterTC позволяет использовать один и тот же код в разных средах.

Такой подход делает современные веб-приложения ближе к нативному программному обеспечению, сохраняя при этом переносимость, безопасность и единый язык разработки.
