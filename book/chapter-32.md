# Часть VIII. JavaScript и искусственный интеллект

## Глава 32. JavaScript и WebAssembly: низкоуровневые вычисления и системная интеграция

К 2026 году **JavaScript** окончательно закрепил за собой роль верховного оркестратора **Web Platform**, гарантирующего бесшовную синергию между высокоуровневой бизнес-логикой и низкоуровневым бинарным кодом, исполняемым через **WebAssembly**. Технология WASM давно переросла статус узкоспециализированного решения для тяжёлых математических задач, превратившись в полноправный элемент универсальной инфраструктуры, стандартизация которой курируется инициативами уровня **WinterTC (TC55)**.

## 32.1. WebAssembly: архитектурный прорыв в производительности

В актуальной экосистеме WebAssembly обеспечивает практически нативную скорость выполнения критически важных вычислительных контуров как на стороне клиентских браузеров, так и в серверных рантаймах.

**Что такое WebAssembly:**

WebAssembly (WASM) — это бинарный формат инструкций для виртуальной машины на основе стека. WASM-модули выполняются в изолированной среде (песочнице) с производительностью, близкой к нативному коду.

**Ключевые характеристики WebAssembly:**

- **Бинарный формат:** Компактный и быстрый для декодирования.
- **Безопасная изоляция:** Модули выполняются в песочнице, не имея прямого доступа к системе.
- **Кросс-платформенность:** Одинаково работает во всех браузерах и серверных рантаймах.
- **Интеграция с JavaScript:** WASM-модули вызываются из JavaScript и наоборот.

**Архитектурная схема взаимодействия:**

```
┌─────────────────────────────────────────────────────────────┐
│                    Приложение на JavaScript                 │
│                                                             │
│  ┌──────────────────────────────────────────────────────┐  │
│  │              JavaScript-код                          │  │
│  │  ┌────────────────────────────────────────────────┐ │  │
│  │  │   Бизнес-логика, UI, координация             │ │  │
│  │  └────────────────────────────────────────────────┘ │  │
│  └────────────────────┬─────────────────────────────────┘  │
│                       │                                     │
│                       ▼                                     │
│  ┌──────────────────────────────────────────────────────┐  │
│  │              WebAssembly-модуль                     │  │
│  │  ┌────────────────────────────────────────────────┐ │  │
│  │  │   Вычисления на Rust/C++/Go/Zig              │ │  │
│  │  └────────────────────────────────────────────────┘ │  │
│  └────────────────────┬─────────────────────────────────┘  │
│                       │                                     │
│                       ▼                                     │
│  ┌──────────────────────────────────────────────────────┐  │
│  │              Аппаратное обеспечение                 │  │
│  │  CPU (с SIMD-инструкциями) / GPU (WebGPU)          │  │
│  └─────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
```

**Пример использования WebAssembly в JavaScript:**

```javascript
// Загрузка WASM-модуля
const response = await fetch('module.wasm');
const bytes = await response.arrayBuffer();
const module = await WebAssembly.compile(bytes);
const instance = await WebAssembly.instantiate(module, {
  env: {
    memory: new WebAssembly.Memory({ initial: 256, maximum: 512 })
  }
});

// Вызов экспортированной функции
const result = instance.exports.calculate(42, 100);
console.log(result); // Результат вычислений в нативной скорости
```

**Memory64: снятие исторического ограничения в 4 ГБ**

Современные среды исполнения поддерживают спецификацию **WebAssembly Memory64**, вошедшую в состав **WebAssembly 3.0** (спецификация опубликована в сентябре 2025 года). Она позволяет приложениям оперировать значительно большими массивами данных в виртуальном адресном пространстве, снимая историческое ограничение линейной памяти WebAssembly версии 1 в 4 ГБ (2³² байт при 32-битной адресации). Важно понимать формулировку точно: теоретический предел новой 64-битной адресации огромен (порядка 16 эксабайт), но реальные браузеры устанавливают собственный практический потолок — как правило, около 16 ГБ, — так что Memory64 стоит воспринимать как значительное расширение, а не как снятие любых ограничений в принципе.

Кросс-браузерная поддержка Memory64 сложилась не сразу: Chrome и Firefox получили её раньше, а Safari — позже остальных, в рамках консолидации функций WebAssembly 3.0 (наряду с WasmGC и другими возможностями). Прежде чем полагаться на Memory64 в продакшене, стоит явно проверять актуальный статус поддержки в целевых браузерах, а не считать её автоматически доступной повсеместно.

**Синтаксис включения 64-битной адресации.** Здесь важно обратить внимание на точный API: параметр называется `address` и принимает не число, а строковое значение `"i64"` (по умолчанию используется `"i32"`). Кроме того, при 64-битной адресации значения `initial` и `maximum` обязаны передаваться как BigInt, а не как обычные числа JavaScript:

```javascript
// Создание памяти с 64-битной адресацией (корректный синтаксис)
const memory = new WebAssembly.Memory({
  initial: 1024n,   // BigInt — обязателен при address: "i64"
  maximum: 16384n,  // BigInt — обязателен при address: "i64"
  address: "i64"    // строка "i64", а не число 64
});
```


**Высокоскоростной мост данных:**

JavaScript-агент осуществляет тонкое управление выделенной памятью посредством универсальных структурных контейнеров (`ArrayBuffer`, `TypedArray`), обеспечивающих нулевое копирование (zero-copy) при транзите потоков байтов между миром JS и скомпилированными модулями.

```javascript
// Разделяемая память между JS и WASM
const sharedBuffer = new SharedArrayBuffer(1024 * 1024);
const typedArray = new Float64Array(sharedBuffer);

// Передача памяти в WASM-модуль
const instance = await WebAssembly.instantiate(module, {
  env: {
    memory: new WebAssembly.Memory({
      initial: 256,
      maximum: 512,
      shared: true // Разделяемая память
    })
  }
});

// WASM-модуль работает с теми же данными без копирования
instance.exports.processData(sharedBuffer);
```

## 32.2. Component Model и WASI: стандартизация бинарных интерфейсов

Важнейшим вектором технологического развития стало повсеместное внедрение компонентной модели **Component Model** и стандартизированного системного интерфейса **WASI (WebAssembly System Interface)**.

**Component Model:**

Component Model — это система типов и интерфейсов для WebAssembly, позволяющая создавать модули, которые могут взаимодействовать друг с другом через стандартизированные интерфейсы, независимо от языка, на котором они написаны.

**Что такое WIT (WebAssembly Interface Types):**

WIT — это язык описания интерфейсов для WebAssembly-компонентов. Он определяет типы данных, функции и их сигнатуры, которые могут быть использованы при взаимодействии компонентов.

```wit
// example.wit
package example:math@1.0.0;

interface math {
    add: func(a: s32, b: s32) -> s32;
    multiply: func(a: f64, b: f64) -> f64;
    vector-sum: func(values: list<f64>) -> f64;
}

world example-world {
    export math;
}
```

**WASI (WebAssembly System Interface):**

WASI — это системный интерфейс для WebAssembly, предоставляющий доступ к файловой системе, сети, времени, случайным числам и другим системным ресурсам в стандартизированном и безопасном виде.

```javascript
// Загрузка WASM-модуля с WASI-поддержкой
import { WASI } from '@wasmer/wasi';

const wasi = new WASI({
  args: ['--help'],
  env: process.env,
  preopens: {
    '/tmp': '/tmp'
  }
});

const instance = await WebAssembly.instantiate(wasmBytes, {
  wasi_snapshot_preview1: wasi.wasiImport
});

wasi.start(instance);
```

**Пример WASM-компонента с WIT-интерфейсом:**

```rust
// Rust-код, компилируемый в WASM
#[derive(Default)]
struct Calculator {
    memory: Vec<f64>,
}

#[no_mangle]
pub extern "C" fn add(a: f64, b: f64) -> f64 {
    a + b
}

#[no_mangle]
pub extern "C" fn multiply(a: f64, b: f64) -> f64 {
    a * b
}

#[no_mangle]
pub extern "C" fn sum_memory() -> f64 {
    let memory = unsafe { MEMORY.as_ref().unwrap() };
    memory.iter().sum()
}
```

**Унификация под эгидой WinterTC:**

Комитет TC55 координирует усилия с рабочими группами W3C, обеспечивая строгую интероперабельность WebAssembly-модулей в разнородных средах выполнения. Это позволяет создавать изоморфные архитектуры, где единый бинарный модуль идентично и безопасно функционирует как в браузере, так и на бэкенде.

**Преимущества Component Model + WASI:**

- **Переносимость:** Один бинарный модуль работает везде.
- **Безопасность:** Доступ к системе контролируется через WASI.
- **Интероперабельность:** Компоненты на разных языках могут взаимодействовать.
- **Производительность:** Нативная скорость выполнения.

## 32.3. Связка JavaScript ↔ Rust: фундамент современного тулинга

**Rust** утвердился в качестве доминирующего системного языка для создания инфраструктурного фундамента всей JavaScript-экосистемы.

**Почему Rust для тулинга JavaScript:**

- **Производительность:** Rust компилируется в нативный код, обеспечивая скорость, сравнимую с C++.
- **Безопасность:** Строгая система типов и управление памятью без сборщика мусора.
- **Интеграция с WASM:** Отличная поддержка компиляции в WebAssembly.
- **Инструменты:** `wasm-pack`, `cargo-generate` и другие инструменты для упрощения разработки.

**Пример: интеграция Rust-библиотеки в JavaScript:**

```rust
// Rust-код (lib.rs)
use wasm_bindgen::prelude::*;

#[wasm_bindgen]
pub fn fibonacci(n: u32) -> u32 {
    if n <= 1 {
        return n;
    }
    let mut a = 0;
    let mut b = 1;
    for _ in 2..=n {
        let temp = a + b;
        a = b;
        b = temp;
    }
    b
}

#[wasm_bindgen]
pub struct Calculator {
    value: f64,
}

#[wasm_bindgen]
impl Calculator {
    #[wasm_bindgen(constructor)]
    pub fn new(initial: f64) -> Calculator {
        Calculator { value: initial }
    }

    pub fn add(&mut self, x: f64) {
        self.value += x;
    }

    pub fn value(&self) -> f64 {
        self.value
    }
}
```

```javascript
// JavaScript-код
import init, { fibonacci, Calculator } from './pkg/wasm_module.js';

await init();

// Использование функции
console.log(fibonacci(40)); // 102334155

// Использование класса
const calc = new Calculator(10);
calc.add(5);
console.log(calc.value()); // 15
```

**Инструментарий нового поколения:**

Переход ключевых сборщиков на архитектуру, написанную на Rust, обеспечивает кратное ускорение операций сборки:

| Инструмент | Бэкенд | Производительность |
| ---------- | ------ | ------------------ |
| Vite 8 | Rolldown (Rust) | 10-30x быстрее |
| Bun | Zig + Rust | 4-5x быстрее Node.js |
| SWC | Rust | 20x быстрее Babel |
| Turbopack | Rust | 10x быстрее Webpack |

**Пример: использование Rust-инструмента из JavaScript:**

```javascript
// Использование SWC (Rust) для компиляции в JavaScript
import { transform } from '@swc/core';

const result = await transform('const x = 1;', {
  jsc: {
    parser: { syntax: 'ecmascript' },
    target: 'es2022'
  }
});

console.log(result.code);
// 'var x = 1;\n'
```

**Экосистема Rust для разработки на JavaScript:**

- `wasm-pack` — сборка Rust-библиотек в WASM.
- `wasm-bindgen` — генерация JavaScript-обёрток для WASM.
- `wasm32-wasi` — компиляция для WASI.
- `cargo-generate` — генерация шаблонов проектов.

## 32.4. Связка JavaScript ↔ C++: преемственность и оптимизация мостов

Несмотря на экспансию Rust, взаимодействие с кодовой базой на **C++** продолжает удерживать ключевые позиции в корпоративном сегменте.

**Почему C++ остаётся актуальным:**

- **Нативные аддоны:** Корпоративные платформы (включая экосистему Node.js) опираются на колоссальный парк проверенных временем C++ модулей, обеспечивающих стабильность и высокую производительность тяжёлых сетевых и дисковых операций.

- **Преемственность:** Существующая инфраструктура (например, V8, Node.js, Electron) написана на C++.

- **Производительность:** C++ обеспечивает максимальную производительность для критических систем.

**Пример: C++ аддон для Node.js:**

```cpp
// C++ код (addon.cc)
#include <node.h>
#include <v8.h>

namespace demo {

using v8::Array;
using v8::Context;
using v8::FunctionCallbackInfo;
using v8::Isolate;
using v8::Local;
using v8::Number;
using v8::Object;
using v8::String;
using v8::Value;

void Sum(const FunctionCallbackInfo<Value>& args) {
  Isolate* isolate = args.GetIsolate();
  
  double sum = 0;
  for (int i = 0; i < args.Length(); i++) {
    sum += args[i].As<Number>()->Value();
  }
  
  args.GetReturnValue().Set(Number::New(isolate, sum));
}

void Init(Local<Object> exports) {
  NODE_SET_METHOD(exports, "sum", Sum);
}

NODE_MODULE(NODE_GYP_MODULE_NAME, Init)

} // namespace demo
```

```javascript
// JavaScript-код
import { sum } from './build/Release/addon.node';

console.log(sum(1, 2, 3, 4, 5)); // 15
```

**Ликвидация накладных расходов моста (Bridge Overhead):**

Передовые рантаймы оптимизируют каналы межъязыкового взаимодействия.

**Пример: встроенный SQLite в Bun:**

```javascript
// Bun имеет нативную интеграцию с SQLite (C++)
import { Database } from 'bun:sqlite';

const db = new Database(':memory:');

db.run(`
  CREATE TABLE users (id INTEGER PRIMARY KEY, name TEXT)
`);

db.run('INSERT INTO users (name) VALUES (?)', ['Alice']);
db.run('INSERT INTO users (name) VALUES (?)', ['Bob']);

const users = db.query('SELECT * FROM users').all();
console.log(users);
// [ { id: 1, name: 'Alice' }, { id: 2, name: 'Bob' } ]
```

**Преимущества нативной интеграции C++:**

- **Нулевая задержка:** Прямая интеграция SQLite исключает классические задержки сериализации при переходе через границу C++/JS.
- **Высокая производительность:** Обработка десятков тысяч транзакций в секунду.
- **Безопасность:** Использование проверенного кода SQLite.

**Сравнение подходов интеграции C++:**

| Подход | Пример | Производительность | Сложность |
| ------ | ------ | ------------------ | --------- |
| Нативный аддон | Node.js addon | Высокая | Высокая |
| WASM-компиляция | C++ → WASM | Средняя | Средняя |
| Встроенный рантайм | Bun с SQLite | Максимальная | Низкая |

## 32.5. Роль JavaScript в экосистеме WASM

JavaScript выполняет роль универсального связующего звена между WebAssembly-модулями, написанными на разных языках:

```
┌─────────────────────────────────────────────────────────────┐
│                    Приложение на JavaScript                 │
│                                                             │
│  ┌─────────────┬─────────────┬─────────────┬─────────────┐ │
│  │  WASM-модуль │  WASM-модуль │  WASM-модуль │  WASM-модуль│ │
│  │  (Rust)     │  (C++)       │  (Go)       │  (Zig)      │ │
│  └─────────────┴─────────────┴─────────────┴─────────────┘ │
│         │            │            │            │          │
│         └────────────┴────────────┴────────────┘          │
│                          │                                 │
│                          ▼                                 │
│              JavaScript-оркестратор                        │
│          (Управление памятью, вызовы, координация)        │
└─────────────────────────────────────────────────────────────┘
```

**Пример: одновременное использование нескольких WASM-модулей:**

```javascript
// Загрузка модулей с разных языков
const rustModule = await WebAssembly.instantiateStreaming(
  fetch('rust-module.wasm')
);

const cppModule = await WebAssembly.instantiateStreaming(
  fetch('cpp-module.wasm')
);

const goModule = await WebAssembly.instantiateStreaming(
  fetch('go-module.wasm')
);

// Координация выполнения в JavaScript
function processData(data) {
  // Этап 1: предобработка на Rust
  const processed = rustModule.exports.preprocess(data);
  
  // Этап 2: основная обработка на C++
  const results = cppModule.exports.process(processed);
  
  // Этап 3: постобработка на Go
  const final = goModule.exports.finalize(results);
  
  return final;
}
```

**Преимущества такого подхода:**

- **Выбор лучшего языка для каждой задачи.**
- **Переиспользование существующих библиотек на разных языках.**
- **Постепенная миграция с C++ на Rust без переписывания всего кода.**
- **Единая точка координации в JavaScript.**

## Заключение

В ландшафте 2026 года JavaScript выступает не просто интерпретатором сценариев, а универсальным связующим звеном («клеем»), координирующим модули на Rust, C++ и других системных языках через WebAssembly.

**WebAssembly** обеспечивает практически нативную скорость выполнения критически важных вычислений через бинарный формат инструкций. **Memory64** снимает ограничение в 4 ГБ памяти, позволяя оперировать гигантскими массивами данных. **Zero-copy** через `ArrayBuffer` и `TypedArray` обеспечивает нулевое копирование при транзите данных между JavaScript и WASM.

**Component Model и WASI** стандартизируют бинарные интерфейсы через WIT (WebAssembly Interface Types), позволяя создавать изоморфные архитектуры, где единый бинарный модуль работает идентично и безопасно как в браузере, так и на бэкенде под координацией WinterTC.

**Связка JavaScript ↔ Rust** стала фундаментом современного тулинга: инструменты нового поколения (Vite 8 с Rolldown, SWC, Turbopack) демонстрируют 10-30-кратное ускорение по сравнению с традиционными скриптовыми инструментами.

**Связка JavaScript ↔ C++** сохраняет ключевые позиции в корпоративном сегменте через нативные аддоны Node.js и интеграцию проверенного кода (например, SQLite в Bun) с нулевой задержкой при переходе через границу C++/JS.

Фокус профессиональной разработки окончательно сместился от написания монолитного кода на чистом JS к высокоуровневому системному проектированию, где JavaScript оркестрирует бинарные компоненты, раскрывая абсолютный потенциал современной **Web Platform**.
