# Часть III. Работа с браузером

# Глава 9. Современная модель событий: интерактивность и жизненный цикл Web Platform

Событийная модель — один из фундаментальных механизмов Web Platform. Именно через события браузер сообщает приложению о действиях пользователя, изменениях состояния документа, сетевых операциях и работе множества встроенных API.

JavaScript не занимается постоянным опросом состояния интерфейса. Вместо этого приложение декларативно регистрирует обработчики, а платформа самостоятельно вызывает их при наступлении соответствующих событий. Такой подход обеспечивает высокую производительность, минимальную нагрузку на процессор и естественную интеграцию с Event Loop.

---

## 9.1. EventTarget — единая модель событий платформы

Практически все современные браузерные API построены вокруг интерфейса **EventTarget**. Он определяет единый контракт для объектов, способных генерировать события, регистрировать обработчики, удалять обработчики и распространять события между участниками системы.

К объектам EventTarget относятся:

- `window` — глобальный объект окна браузера.
- `document` — корневой объект HTML-документа.
- Любые DOM-элементы — `div`, `button`, `input`, `form` и другие.
- `AbortSignal` — сигнал для отмены операций.
- `Worker` — Web Worker для фоновых вычислений.
- `WebSocket` — объект для двунаправленной связи с сервером.
- `BroadcastChannel` — канал для обмена сообщениями между вкладками.
- Многие другие API платформы — `EventSource`, `XMLHttpRequest`, `MediaQueryList`.

Благодаря этому независимо от источника события разработчик использует один и тот же механизм:

```javascript
target.addEventListener(type, listener, options);
target.removeEventListener(type, listener);
target.dispatchEvent(event);
```

- `addEventListener()` — регистрирует обработчик события. Принимает три параметра: тип события (строка), функцию-обработчик и объект настроек (или булево значение для capture).
- `removeEventListener()` — удаляет ранее зарегистрированный обработчик. Для корректного удаления необходимо передать ту же функцию и те же настройки, что использовались при регистрации.
- `dispatchEvent()` — синхронно вызывает все зарегистрированные обработчики для указанного типа события на текущем объекте.

Единая модель событий делает Web Platform внутренне согласованной и позволяет легко переносить знания между различными API. Один и тот же паттерн работы с событиями применяется к DOM-элементам, WebSocket, Worker и другим объектам.

## 9.2. Распространение событий

После возникновения события браузер распространяет его по дереву DOM. Этот процесс состоит из трёх фаз.

### Capture Phase (фаза захвата)

Событие движется сверху вниз — от корня документа к целевому элементу:

```
window
 ↓
document
 ↓
html
 ↓
body
 ↓
button (целевой элемент)
```

Обработчики выполняются только если зарегистрированы с опцией `capture: true`. Эта фаза редко используется в обычных приложениях, но полезна для перехвата событий перед тем, как они достигнут целевого элемента.

```javascript
element.addEventListener('click', handler, { capture: true });
```

---

### Target Phase (фаза цели)

Событие достигает элемента, который его породил. Например, когда пользователь кликает на кнопку, событие достигает этой кнопки. Обработчики, зарегистрированные непосредственно на целевом элементе, выполняются именно на этой фазе.

---

### Bubble Phase (фаза всплытия)

После обработки на целевом элементе событие начинает подниматься обратно вверх:

```
button
 ↑
body
 ↑
html
 ↑
document
 ↑
window
```

Именно эта фаза используется чаще всего, поскольку позволяет регистрировать обработчики на родительских элементах и обслуживать события всех потомков.

**Делегирование событий (Event Delegation)** — подход, при котором обработчик регистрируется на родительском элементе, а не на каждом дочернем элементе отдельно. Внутри обработчика определяется, какой конкретный элемент породил событие, с помощью свойства `event.target`.

```javascript
document.getElementById('list').addEventListener('click', (event) => {
  const item = event.target.closest('li');
  if (item) {
    console.log('Клик на элементе:', item.textContent);
  }
});
```

Делегирование значительно уменьшает количество обработчиков в больших интерфейсах, упрощает управление памятью и автоматически обрабатывает динамически добавляемые элементы.

**Остановка распространения:**

- `event.stopPropagation()` — предотвращает дальнейшее распространение события по дереву DOM (всплытие или захват).
- `event.stopImmediatePropagation()` — предотвращает распространение и немедленно останавливает выполнение других обработчиков на том же элементе.

## 9.3. Современный addEventListener()

Современный JavaScript практически всегда использует объект настроек вместо устаревшего третьего булевого параметра (который интерпретировался как `capture`).

Наиболее важные параметры:

### `once`

После первого вызова обработчик автоматически удаляется. Это удобно для одноразовых действий, например, подтверждения после первого клика.

```javascript
button.addEventListener('click', save, { once: true });
// После первого клика обработчик будет удалён
```

---

### `passive`

Сообщает браузеру, что обработчик никогда не вызовет `preventDefault()`. Это позволяет браузеру выполнять прокрутку страницы без ожидания завершения JavaScript-кода, что особенно важно для плавной работы интерфейса.

```javascript
window.addEventListener('scroll', updateHeader, { passive: true });
```

Если в passive-обработчике вызвать `preventDefault()`, браузер проигнорирует вызов и может выдать предупреждение в консоли. Использование `passive` обязательно для событий `touchstart`, `touchmove` и `wheel`, чтобы обеспечить плавную прокрутку.

---

### `capture`

Позволяет выполнять обработчик во время фазы захвата, а не всплытия.

```javascript
element.addEventListener('click', handler, { capture: true });
```

Полезно для перехвата событий до того, как они достигнут целевого элемента.

---

### `signal`

Связывает обработчик с объектом `AbortSignal`. После отмены сигнала обработчик автоматически удаляется. Это избавляет приложение от необходимости вручную вызывать `removeEventListener()`.

```javascript
const controller = new AbortController();
button.addEventListener('click', handler, { signal: controller.signal });
// Позже: controller.abort() — обработчик будет удалён
```

## 9.4. Управление жизненным циклом через AbortController

Одним из самых важных современных API платформы стал механизм отмены операций. `AbortController` первоначально появился для отмены сетевых запросов, но сегодня используется практически всеми современными браузерными API.

```javascript
const controller = new AbortController();

button.addEventListener('click', handler, { signal: controller.signal });
fetch('/api/data', { signal: controller.signal });

// Отмена всех операций
controller.abort();
```

После вызова `abort()` браузер автоматически:

- удаляет связанные обработчики событий;
- отменяет запросы `fetch` с этим сигналом;
- завершает другие операции, поддерживающие `AbortSignal`.

Это значительно уменьшает вероятность утечек памяти и гарантирует, что после уничтожения компонента не останется "висящих" обработчиков.

**Современные статические методы AbortSignal:**

`AbortSignal.timeout()` — создаёт сигнал, автоматически отменяющийся через указанное время в миллисекундах.

```javascript
const signal = AbortSignal.timeout(5000);
fetch('/api/data', { signal });
// Если запрос не завершился за 5 секунд, он будет отменён
```

`AbortSignal.any()` — объединяет несколько сигналов. Результирующий сигнал отменяется сразу после отмены любого из них.

```javascript
const controller = new AbortController();
const signal = AbortSignal.any([
  controller.signal,                    // Отмена пользователем
  AbortSignal.timeout(5000)             // Таймаут 5 секунд
]);

fetch('/api/data', { signal });
// Запрос отменится при отмене пользователем, по таймауту
```

Подобная композиция позволяет легко объединять отмену пользователем, таймауты и жизненный цикл компонентов.

## 9.5. Современные события ввода

Развитие аппаратных устройств привело к унификации событий пользовательского ввода.

### Pointer Events

Pointer Events стали рекомендуемым API для обработки взаимодействия пользователя. В отличие от старых Mouse Events они одинаково работают с мышью, сенсорными экранами, стилусом и цифровым пером.

Основные события Pointer Events:

- `pointerdown` — указатель нажат.
- `pointerup` — указатель отпущен.
- `pointermove` — указатель перемещён.
- `pointerenter` — указатель вошёл в элемент.
- `pointerleave` — указатель покинул элемент.
- `pointercancel` — событие прервано (например, системой).

Кроме координат указателя (`clientX`, `clientY`) доступны дополнительные параметры:

- `pressure` — сила нажатия (от 0 до 1).
- `tiltX`, `tiltY` — угол наклона пера.
- `width`, `height` — контактная площадь.
- `pointerType` — тип устройства: `'mouse'`, `'touch'`, `'pen'`.

```javascript
element.addEventListener('pointerdown', (event) => {
  console.log('Тип устройства:', event.pointerType);
  console.log('Сила нажатия:', event.pressure);
});
```

Использование одного API позволяет отказаться от отдельных обработчиков для мыши и сенсорных экранов, упрощая код и обеспечивая одинаковый опыт на всех устройствах.

---

### Keyboard Events

Для обработки клавиатуры используются два основных свойства:

- `key` — введённый символ (например, `'a'`, `'Enter'`, `' '`). Учитывает текущую раскладку клавиатуры.
- `code` — физическая клавиша (например, `'KeyQ'`, `'Digit1'`, `'Space'`). Не зависит от раскладки.

```javascript
document.addEventListener('keydown', (event) => {
  console.log('Символ:', event.key);      // 'q' или 'й' в зависимости от раскладки
  console.log('Физическая клавиша:', event.code); // 'KeyQ' всегда
});
```

Например, `'KeyQ'` всегда означает физическую клавишу Q независимо от раскладки клавиатуры. В то время как `event.key` вернёт `'q'` для английской раскладки и `'й'` для русской. Такое разделение особенно важно для игр (где важна физическая клавиша), редакторов (где важен введённый символ) и доступных интерфейсов.

---

### Input Events

Событие `input` возникает при каждом изменении содержимого элемента управления (текстовое поле, текстовое поле, выбор из списка). Это делает его основой современных реактивных интерфейсов.

```javascript
inputElement.addEventListener('input', (event) => {
  const value = event.target.value;
  updateUI(value); // Обновление интерфейса при каждом изменении
});
```

Событие `change` возникает только после завершения редактирования — при потере фокуса или нажатии Enter. Для синхронизации состояния приложения обычно используют именно `input`, поскольку оно обеспечивает мгновенную обратную связь.

## 9.6. Пользовательские события

Событийная модель Web Platform не ограничивается встроенными событиями браузера. Приложения могут самостоятельно создавать собственные события при помощи `CustomEvent`.

```javascript
const event = new CustomEvent('user:login', {
  detail: {
    userId: 42,
    username: 'alice'
  }
});
document.dispatchEvent(event);
```

Дополнительные данные передаются через свойство `detail`. Это может быть любое JavaScript-значение — объект, массив, примитив.

**Пример использования пользовательских событий для слабосвязанной архитектуры:**

```javascript
// Компонент авторизации
function loginComponent() {
  const login = () => {
    const user = { id: 42, name: 'Alice' };
    document.dispatchEvent(new CustomEvent('user:logged-in', {
      detail: { user },
      bubbles: true
    }));
  };
  // ...
}

// Компонент профиля, реагирующий на вход
document.addEventListener('user:logged-in', (event) => {
  const { user } = event.detail;
  console.log('Пользователь вошёл:', user.name);
});
```

Пользовательские события позволяют строить слабосвязанные архитектуры, в которых компоненты взаимодействуют друг с другом без прямых зависимостей. Компонент авторизации не должен знать о существовании компонента профиля — он просто генерирует событие, а все заинтересованные компоненты подписываются на него.

## 9.7. Лучшие практики современной разработки

Современные приложения придерживаются нескольких простых принципов работы с событиями:

1. **Использовать делегирование событий** вместо большого количества отдельных обработчиков. Это уменьшает нагрузку на память и упрощает управление динамическими элементами.

2. **Передавать объект настроек в `addEventListener()`** вместо устаревшего булевого параметра. Это делает код более читаемым и позволяет использовать современные опции.

3. **Использовать `AbortController` для управления жизненным циклом обработчиков.** Это гарантирует удаление обработчиков при уничтожении компонентов и предотвращает утечки памяти.

4. **Для новых проектов применять `Pointer Events`** вместо отдельных обработчиков мыши и сенсорного ввода. Это обеспечивает унифицированную обработку на всех устройствах.

5. **Использовать событие `input` для реактивных интерфейсов**, а `change` — для случаев, когда требуется подтверждение завершения редактирования.

6. **Передавать данные между независимыми компонентами через `CustomEvent`**, а не через глобальные переменные или прямые вызовы методов. Это снижает связанность компонентов.

7. **Всегда использовать `passive: true` для событий прокрутки** (`scroll`, `touchmove`, `wheel`), чтобы обеспечить плавную работу интерфейса.

8. **Регулярно удалять обработчики** при уничтожении компонентов — через `AbortController` или явный вызов `removeEventListener()`.

## Заключение главы

Современная событийная модель Web Platform представляет собой единую инфраструктуру взаимодействия между JavaScript и браузером. Интерфейс `EventTarget` обеспечивает единый контракт для всех объектов, способных генерировать события — от DOM-элементов до WebSocket и Worker. Механизм распространения событий с фазами захвата, цели и всплытия позволяет гибко обрабатывать события как на конкретных элементах, так и через делегирование. Современный `addEventListener()` с объектом настроек предоставляет декларативные возможности — `once` для одноразовых обработчиков, `passive` для плавной прокрутки, `signal` для автоматического управления жизненным циклом через `AbortController`. `AbortController` стал универсальным механизмом отмены операций, поддерживаемый Fetch, событиями, Streams и другими API. Унифицированные события ввода — Pointer Events, Keyboard Events и Input Events — обеспечивают одинаковый опыт на всех типах устройств. Пользовательские события на основе `CustomEvent` позволяют строить слабосвязанные архитектуры с минимальной связностью между компонентами. В экосистеме 2026 года JavaScript не занимается постоянным управлением состоянием интерфейса — он описывает реакцию приложения на события, а Web Platform самостоятельно обеспечивает доставку событий, управление жизненным циклом обработчиков и эффективное выполнение всей инфраструктуры взаимодействия.
