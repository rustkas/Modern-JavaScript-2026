# Часть IV. Современная работа с данными

## Глава 13. Fetch API: современный стандарт сетевого взаимодействия

К 2026 году **Fetch API** стал основным стандартом выполнения HTTP-запросов во всей экосистеме JavaScript. Один и тот же интерфейс используется в браузерах, а также поддерживается современными серверными средами выполнения — **Node.js** (начиная с версии 18), **Deno** и **Bun**. Благодаря этому разработчики могут использовать единый подход к работе с сетью независимо от места выполнения приложения.

В отличие от устаревшего `XMLHttpRequest`, Fetch API основан на промисах, поддерживает потоковую обработку данных, легко интегрируется с `async/await`, `AbortController` и Web Streams, а также предоставляет объектную модель для работы с запросами и ответами.

---

## 13.1. Функция `fetch()`: универсальный интерфейс сетевых запросов

Функция `fetch()` отправляет HTTP-запрос и возвращает объект `Promise`, который после завершения операции содержит объект `Response`. Базовый синтаксис:

```javascript
const response = await fetch('https://api.example.com/data');
const data = await response.json();
console.log(data);
```

Современная модель работы выглядит следующим образом:

1. Создаётся описание запроса (URL, метод, заголовки, тело).
2. Браузер или серверный рантайм выполняет сетевое взаимодействие.
3. После получения ответа (статус, заголовки) промис завершается.
4. Приложение начинает обработку данных (чтение тела ответа).

**Важное поведение:** Промис, возвращаемый `fetch()`, отклоняется только при сетевых ошибках (например, отсутствие соединения, некорректный URL, сбой DNS). Ошибки HTTP-статусов (404, 500 и т.д.) не приводят к отклонению промиса — они обрабатываются через проверку свойства `response.ok`.

```javascript
const response = await fetch('/api/users');
if (!response.ok) {
  console.log(`Ошибка HTTP: ${response.status}`);
  return;
}
const data = await response.json();
```

На практике `fetch()` почти всегда используется совместно с `async/await`, что делает асинхронный код последовательным и легко читаемым. Однако возможна и работа с промисами напрямую:

```javascript
fetch('/api/data')
  .then(response => response.json())
  .then(data => console.log(data))
  .catch(error => console.error('Ошибка сети:', error));
```

Современные реализации Fetch автоматически используют возможности транспортного уровня:

- **HTTP/2 и HTTP/3** — мультиплексирование запросов по одному соединению, сжатие заголовков.
- **Повторное использование соединений** — соединения переиспользуются для нескольких запросов.
- **Приоритеты** — автоматическое управление приоритетами на уровне протокола.

Поэтому разработчику не требуется самостоятельно управлять сокетами или сетевыми буферами.

## 13.2. Объекты `Request` и `Response`

Fetch API построен вокруг двух основных объектов — `Request` и `Response`.

### `Request`

Объект `Request` полностью описывает исходящий запрос. Он содержит:

- **URL** — целевой адрес запроса.
- **HTTP-метод** — `GET`, `POST`, `PUT`, `DELETE`, `PATCH` и другие.
- **Заголовки** — объект `Headers` с HTTP-заголовками.
- **Тело запроса** — может быть строкой, `Blob`, `ArrayBuffer`, `FormData`, `ReadableStream` или `URLSearchParams`.
- **Режим CORS** — `'cors'`, `'same-origin'`, `'no-cors'`.
- **Настройки кэширования** — `'default'`, `'no-store'`, `'reload'`, `'force-cache'`, `'only-if-cached'`.
- **Режим перенаправлений** — `'follow'`, `'manual'`, `'error'`.
- **Приоритет загрузки** — `'high'`, `'low'`, `'auto'`.
- **Сигнал отмены** — `AbortSignal` для отмены запроса.

Поскольку `Request` является полноценным объектом, его можно создавать заранее, хранить, модифицировать и повторно использовать:

```javascript
const request = new Request('https://api.example.com/users', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    'Authorization': 'Bearer token123'
  },
  body: JSON.stringify({ name: 'Alice' })
});

// Использование одного и того же запроса
const response1 = await fetch(request);
const response2 = await fetch(request.clone()); // Клонирование для повторного использования
```

### `Response`

Объект `Response` представляет полученный ответ сервера. Он содержит:

- **Код состояния** — `response.status` (числовой код).
- **Признак успешного выполнения** — `response.ok` (true для статусов 200-299).
- **Заголовки ответа** — доступные через `response.headers`.
- **Поток данных** — `response.body` (объект `ReadableStream`).
- **Методы получения содержимого** — для чтения тела ответа.

Наиболее используемые методы:

- `response.json()` — парсит тело как JSON и возвращает объект.
- `response.text()` — возвращает тело как строку.
- `response.blob()` — возвращает тело как `Blob` (для файлов, изображений).
- `response.arrayBuffer()` — возвращает тело как `ArrayBuffer` (для бинарных данных).
- `response.formData()` — возвращает тело как `FormData` (для отправки форм).

Каждый из этих методов возвращает промис, поскольку чтение тела ответа также является асинхронной операцией.

```javascript
const response = await fetch('/api/user/avatar');
const blob = await response.blob();
const imageUrl = URL.createObjectURL(blob);
```

**Особенность:** Тело ответа можно прочитать только один раз. Если необходимо использовать данные несколько раз, следует использовать `response.clone()` перед чтением.

```javascript
const response = await fetch('/api/data');
const clone = response.clone();
const data1 = await response.json();
const data2 = await clone.text();
```

## 13.3. Заголовки HTTP и объект `Headers`

Для работы с HTTP-заголовками Fetch API предоставляет специальный объект `Headers`. Вместо работы с обычными объектами JavaScript используется специализированный интерфейс, который:

- автоматически приводит имена заголовков к единому виду (все имена заголовков регистронезависимы);
- корректно обрабатывает повторяющиеся значения (некоторые заголовки могут иметь несколько значений);
- предоставляет методы `get()`, `set()`, `append()`, `delete()` и `has()`;
- поддерживает итерацию через `for...of`.

```javascript
const headers = new Headers();
headers.set('Content-Type', 'application/json');
headers.append('Authorization', 'Bearer token123');
headers.append('X-Custom-Header', 'value1');
headers.append('X-Custom-Header', 'value2');

console.log(headers.get('content-type')); // 'application/json' (регистронезависимо)
console.log(headers.get('x-custom-header')); // 'value1, value2' (объединение)
console.log(headers.has('Authorization')); // true
headers.delete('Authorization');
```

**Использование с fetch:**

```javascript
const headers = new Headers({
  'Content-Type': 'application/json',
  'Authorization': 'Bearer token123'
});

const response = await fetch('/api/data', { headers });
```

**Чтение заголовков ответа:**

```javascript
const response = await fetch('/api/data');
console.log(response.headers.get('content-type'));
console.log(response.headers.get('cache-control'));

// Итерация по заголовкам
for (const [name, value] of response.headers) {
  console.log(`${name}: ${value}`);
}
```

Использование `Headers` снижает вероятность ошибок при работе с HTTP-протоколом, поскольку все имена заголовков автоматически нормализуются, и делает код более переносимым между различными реализациями Fetch.

## 13.4. Потоковая обработка данных через Streams API

Одним из важнейших преимуществ современного Fetch API является встроенная поддержка **Web Streams API**. Свойство `response.body` представляет собой объект `ReadableStream`, который позволяет читать данные по частям по мере их поступления.

```javascript
const response = await fetch('https://api.example.com/large-data');
const reader = response.body.getReader();
const decoder = new TextDecoder();

let result = '';
while (true) {
  const { done, value } = await reader.read();
  if (done) break;
  result += decoder.decode(value, { stream: true });
}
```

Это означает, что приложение может начинать обработку данных сразу после поступления первых байтов, не ожидая завершения всей загрузки.

**Практические сценарии потоковой обработки:**

- **Загрузка больших JSON-документов** — парсинг по частям без загрузки всего файла в память.
- **Потоковый HTML-рендеринг** — отображение контента по мере его поступления от сервера.
- **Воспроизведение видео и аудио** — буферизация и воспроизведение до полной загрузки.
- **Обработка больших CSV-файлов** — чтение и обработка по строкам.
- **Генеративные модели ИИ** — обработка потоковых ответов от AI-моделей, которые возвращают результат по токенам.

```javascript
// Пример обработки потокового JSON (JSON Streaming)
async function processStream(url) {
  const response = await fetch(url);
  const reader = response.body.pipeThrough(new TextDecoderStream()).getReader();
  
  let buffer = '';
  while (true) {
    const { done, value } = await reader.read();
    if (done) break;
    buffer += value;
    // Обработка чанков JSON (например, разделение по строкам)
    const lines = buffer.split('\n');
    buffer = lines.pop() || '';
    for (const line of lines) {
      if (line) {
        const data = JSON.parse(line);
        handleData(data);
      }
    }
  }
}
```

Потоковая обработка позволяет существенно уменьшить потребление памяти (не нужно хранить весь ответ целиком) и сократить время отклика интерфейса (данные отображаются по мере поступления).

## 13.5. Управление жизненным циклом запросов

Любой современный сетевой запрос должен иметь возможность быть отменённым. Для этого Fetch API использует механизм `AbortController` и `AbortSignal`.

```javascript
// Создание контроллера
const controller = new AbortController();
const signal = controller.signal;

// Передача сигнала в fetch
const response = await fetch('/api/data', { signal });

// Отмена запроса
controller.abort();
```

После вызова `controller.abort()` браузер прекращает выполнение запроса, освобождая сетевые и вычислительные ресурсы. Промис `fetch()` отклоняется с ошибкой `AbortError`.

```javascript
try {
  const response = await fetch('/api/data', { signal });
} catch (error) {
  if (error.name === 'AbortError') {
    console.log('Запрос был отменён');
  } else {
    console.error('Ошибка:', error);
  }
}
```

**Современные дополнительные инструменты:**

- **`AbortSignal.timeout(ms)`** — автоматически отменяет запрос через заданное время в миллисекундах.

```javascript
const signal = AbortSignal.timeout(5000); // 5 секунд
const response = await fetch('/api/data', { signal });
```

- **`AbortSignal.any([...signals])`** — объединяет несколько сигналов отмены в один. Результирующий сигнал отменяется при отмене любого из них.

```javascript
const userController = new AbortController();
const timeoutSignal = AbortSignal.timeout(5000);
const combinedSignal = AbortSignal.any([
  userController.signal,
  timeoutSignal,
  abortOnComponentDestroy.signal
]);

const response = await fetch('/api/data', { signal: combinedSignal });
```

Это позволяет одновременно учитывать различные причины прекращения операции:

- истечение тайм-аута;
- уход пользователя со страницы;
- удаление компонента интерфейса;
- явную отмену пользователем (кнопка "Отмена");
- переход на другую страницу.

Такой подход значительно упрощает управление жизненным циклом сетевых операций и предотвращает накопление устаревших запросов, что является частой причиной утечек памяти и нежелательного поведения интерфейса.

## 13.6. Приоритет загрузки ресурсов

Fetch API позволяет сообщить браузеру относительную важность запроса при помощи свойства `priority`.

```javascript
// Высокий приоритет — критичные ресурсы
fetch('/hero-image.jpg', { priority: 'high' });

// Низкий приоритет — фоновые загрузки
fetch('/analytics.js', { priority: 'low' });
```

Возможные значения:

- **`'high'`** — запрос с высоким приоритетом (например, критичные изображения, основной контент).
- **`'auto'`** — приоритет определяется автоматически (значение по умолчанию).
- **`'low'`** — запрос с низким приоритетом (аналитика, предзагрузка некритичных данных).

Стоит уточнить статус этой возможности: `priority` в Fetch API (и связанный с ним HTML-атрибут `fetchpriority`) реализованы во всех основных браузерах — Chrome и Edge с 2022 года, Safari с версии 17.2 (декабрь 2023), Firefox — последним, с версии 132 (октябрь 2024). Технология достигла статуса **Baseline Newly Available** в октябре 2024 года, однако статус **Baseline Widely Available** ожидается только к апрелю 2027 года — то есть формально ещё не прошло достаточно времени с момента полной кросс-браузерной поддержки.

**Важно понимать:** Приоритет является рекомендацией для браузера, а не обязательной командой. Браузер самостоятельно принимает окончательное решение с учётом:

- текущей загрузки сети;
- типа ресурса (изображения, скрипты, CSS, данные);
- собственной политики планировщика;
- особенностей HTTP/2 или HTTP/3 (приоритеты на уровне протокола);
- возможностей CDN и сервера.

Практическое следствие из необязательности этой подсказки: на неё нельзя полагаться как на функциональную зависимость. Например, ошибочно рассчитывать, что `priority: 'low'` гарантированно предотвратит конкуренцию фонового запроса с загрузкой критичного для LCP (Largest Contentful Paint) ресурса на всех браузерах — в движке, который параметр игнорирует, конкуренция за пропускную способность сети вернётся. Если браузер не поддерживает `priority`, он просто применяет приоритет по умолчанию, ничего не ломая, но и не давая ожидаемого эффекта.

Тем не менее правильная расстановка приоритетов помогает браузеру быстрее загружать наиболее важные ресурсы страницы, улучшая воспринимаемую производительность и User Experience.

## 13.7. Универсальный Fetch в современных средах выполнения

Одним из главных изменений последних лет стало распространение Fetch API далеко за пределы браузера.

Современные версии:

- **Node.js** — начиная с версии 18, `fetch()` доступен как глобальная функция (ранее требовались сторонние библиотеки, такие как `node-fetch`).
- **Deno** — `fetch()` доступен с самого начала (изначально встроен в среду).
- **Bun** — полная поддержка `fetch()` с высокой производительностью.

Благодаря инициативам **WinterTC** и унификации Web API разработчики всё чаще пишут один и тот же сетевой код, который одинаково работает в разных средах. Здесь важно уточнить актуальный организационный статус этой инициативы: изначально работа велась в открытой рабочей группе W3C — **WinterCG** (Web-interoperable Runtimes Community Group), — но в январе 2025 года эта группа была закрыта, а её работа передана в **Ecma International**, тот же орган, что стандартизирует через TC39 сам язык. Актуальное официальное название — **Ecma TC55**, неформально по-прежнему именуемое **WinterTC**.

Такой код одинаково работает:

- в браузере (клиентские приложения);
- на сервере (Node.js, Deno, Bun);
- в серверных функциях (Serverless, Lambda);
- в Edge Runtime (Cloudflare Workers, Vercel Edge);
- в Web Workers (фоновые вычисления);
- в Service Workers (офлайн-режим, кеширование).

```javascript
// Один и тот же код работает везде
async function fetchUserData(userId) {
  const response = await fetch(`/api/users/${userId}`);
  if (!response.ok) {
    throw new Error(`HTTP error: ${response.status}`);
  }
  return response.json();
}
```

Различия между платформами постепенно сокращаются:

- **URL-адресация** — браузеры используют абсолютные URL, Node.js и Deno поддерживают относительные пути с указанием `baseUrl`.
- **Кэширование** — в браузерах работает HTTP-кеш, на сервере требуется ручное управление кешированием.
- **CORS** — в браузере действуют политики CORS, на сервере они отсутствуют.

Несмотря на эти различия, основная логика работы с `fetch()` остаётся одинаковой, что делает экосистему JavaScript значительно более целостной и позволяет переиспользовать код между клиентом и сервером.

## Заключение главы

Fetch API стал универсальным интерфейсом сетевого взаимодействия в современной экосистеме JavaScript. Он объединяет удобную объектную модель (`Request`, `Response`, `Headers`), потоковую обработку данных через Streams API, безопасное управление жизненным циклом запросов с помощью `AbortController` и единый подход к работе с сетью в браузерах и серверных средах.

Функция `fetch()` возвращает промис, который разрешается с объектом `Response`, содержащим статус, заголовки и поток данных. Объекты `Request` и `Response` позволяют полностью описать запрос и обработать ответ. `Headers` предоставляет безопасную работу с HTTP-заголовками. Streams API позволяет обрабатывать данные по частям без загрузки всего ответа в память. `AbortController` обеспечивает отмену запросов по таймауту, действиям пользователя или уничтожению компонентов. Приоритеты (`priority`) помогают браузеру оптимизировать загрузку ресурсов.

Современный JavaScript практически не занимается низкоуровневой реализацией сетевых протоколов. Его задача — описать намерения приложения: какой ресурс необходимо получить, как обработать поток данных, когда отменить запрос и какие приоритеты ему назначить. Всё остальное выполняют оптимизированные механизмы Web Platform и современных сред выполнения.
