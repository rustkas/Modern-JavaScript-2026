# Предисловие

## Глава 1. JavaScript 2026: язык современной Web Platform

За тридцать лет существования JavaScript прошёл путь от небольшого языка сценариев для браузера до универсальной платформы разработки. Сегодня на JavaScript создают пользовательские интерфейсы, серверные приложения, облачные функции, инструменты автоматизации, системы искусственного интеллекта и программное обеспечение для настольных компьютеров.

Однако главным изменением последних лет стала не очередная языковая возможность, а изменение самой философии разработки. Современный JavaScript — это уже не только ECMAScript, а совокупность языка, стандартных Web API, модульной системы, инструментов сборки и единой платформенной экосистемы.

Эта книга посвящена именно современному JavaScript образца 2026 года.

---

## 1.1. JavaScript сегодня: больше чем язык

Современная разработка строится вокруг нескольких взаимосвязанных уровней.

- **ECMAScript** — определяет синтаксис языка, типы данных, функции, классы, модули, асинхронное программирование и стандартную библиотеку (`Array`, `Map`, `Set`, `Promise` и другие). Это фундамент, на котором строится всё остальное.

- **Web Platform** — предоставляет тысячи API для работы с сетью (Fetch), файлами (File API), потоками данных (Streams), графикой (Canvas, WebGPU), мультимедиа (WebAudio, WebRTC) и устройствами (Bluetooth, USB, Serial). Без этих API JavaScript был бы просто абстрактным языком — с ними он становится полноценной платформой.

- **JavaScript Runtime** — среда выполнения (браузер, Node.js, Deno, Bun), которая обеспечивает доступ к API платформы, управляет памятью, выполняет код и предоставляет системные возможности (файловая система, сеть, процессы).

- **Инструменты разработки** — автоматизируют сборку (Vite, Rollup, esbuild), тестирование (Vitest, Jest), анализ кода (ESLint), форматирование (Prettier), управление зависимостями (npm, pnpm) и публикацию приложений.

Именно взаимодействие этих уровней определяет современный JavaScript, а не отдельные языковые конструкции. Разработчик должен понимать, как язык (ECMAScript) взаимодействует с платформой (Web API), как выполняется в конкретной среде (Runtime) и какие инструменты упрощают разработку.

## 1.2. Как развивается ECMAScript

Стандарт ECMAScript развивается непрерывно. Каждый год комитет **TC39** (Technical Committee 39) публикует новую редакцию языка, включающую только полностью завершённые предложения.

Новые возможности проходят несколько стадий стандартизации:

- **Stage 0 (Strawman)** — идея, представленная для обсуждения. На этом этапе нет спецификации, только описание проблемы.
- **Stage 1 (Proposal)** — формальное предложение. Комитет рассматривает идею и решает, стоит ли её развивать. Появляется черновик спецификации.
- **Stage 2 (Draft)** — проект спецификации. Предложение имеет формальное описание на языке ECMAScript. Начинается реализация экспериментальных версий в движках.
- **Stage 3 (Candidate)** — готовность к реализации. Спецификация завершена, ожидаются отзывы от реализаторов (браузеров, Node.js). На этом этапе изменения возможны только для исправления критических проблем.
- **Stage 4 (Finished)** — включение в стандарт. Предложение реализовано в как минимум двух независимых движках и прошло тестирование. На следующем ежегодном обновлении ECMAScript оно становится частью официального стандарта.

Благодаря такой модели язык развивается постепенно, без революционных изменений, сохраняя обратную совместимость. Новые возможности не ломают существующий код, что позволяет крупным проектам обновляться постепенно.

Именно поэтому современный JavaScript ощущается как единый язык, который ежегодно становится немного лучше, а не переписывается заново каждые несколько лет. Разработчик может изучать новые возможности по мере их появления, не опасаясь, что его знания устареют.

## 1.3. JavaScript как Living Standard

Несмотря на ежегодные редакции стандарта, сама спецификация развивается непрерывно. Практически все предложения публикуются задолго до официального релиза, обсуждаются сообществом, реализуются в движках и проходят длительное тестирование.

Например, Top-Level Await был доступен в браузерах задолго до его включения в стандарт ES2022. Это означает, что разработчики могли использовать эту возможность, не дожидаясь официального выхода стандарта.

Поэтому современный разработчик ориентируется сразу на несколько источников информации:

- **Официальный стандарт ECMAScript** — финальная спецификация языка (https://tc39.es/ecma262/).
- **Предложения TC39** — новые возможности, находящиеся на разных стадиях рассмотрения (https://github.com/tc39/proposals).
- **Документацию MDN** — практическое руководство по использованию языка и API (https://developer.mozilla.org/).
- **Статус поддержки браузерами** — информацию о том, какие возможности уже работают в конкретных браузерах (https://caniuse.com/, https://chromestatus.com/).
- **Рекомендации Baseline** — оценку готовности технологии к промышленному использованию (https://web.dev/baseline/).

Изучение языка постепенно превращается в изучение постоянно развивающейся платформы. Разработчик должен уметь ориентироваться в этих источниках, чтобы понимать, какие возможности можно использовать в своих проектах.

## 1.4. Эпоха Baseline

Одним из главных изменений последних лет стала модель **Baseline** — подход к оценке готовности Web-технологий к промышленному использованию. Baseline был предложен Google, Mozilla и другими участниками Web Platform для упрощения принятия инженерных решений.

Раньше разработчики ориентировались на версии браузеров: "Поддерживает ли Chrome 98 эту возможность?". Это требовало постоянного отслеживания таблиц совместимости и учета множества версий.

Сегодня гораздо важнее знать, относится ли возможность к категории:

- **Baseline Widely Available** — технология поддерживается во всех основных браузерах (Chrome, Firefox, Safari, Edge) не менее 30 месяцев (2.5 года). Это означает, что подавляющее большинство пользователей уже используют браузеры с поддержкой этой технологии. Можно использовать без полифилов практически в любом проекте.

- **Baseline Newly Available** — технология только что стала поддерживаться во всех основных браузерах. Она уже стандартизирована и готова к использованию, но требует оценки совместимости с аудиторией проекта. Можно использовать с осторожностью, оценивая, какая доля пользователей уже обновила браузеры.

- **Limited Availability (доступно ограниченно)** — технология ещё не поддерживается во всех основных браузерах. Следует использовать полифилы или воздержаться от использования в продакшене.

Такой подход значительно упрощает принятие инженерных решений и постепенно заменяет традиционные таблицы совместимости. Вместо проверки десятков версий браузеров разработчик просто проверяет статус технологии в Baseline.

## 1.5. Современные среды выполнения

JavaScript больше не ограничивается браузером. Сегодня существуют несколько полноценных сред выполнения:

- **Browser (браузер)** — клиентские приложения, пользовательские интерфейсы, взаимодействие с DOM, Canvas, WebGL, WebGPU. Основные браузеры: Chrome, Firefox, Safari, Edge.

- **Node.js** — серверная разработка и инфраструктура. Предоставляет доступ к файловой системе, HTTP-серверу, процессам, сетевым сокетам. Основан на движке V8. Широко используется для бэкенда, инструментов командной строки, сборки проектов.

- **Deno** — современная безопасная среда выполнения от создателя Node.js (Ryan Dahl). Поддерживает TypeScript из коробки, имеет встроенные утилиты (форматирование, линтинг, тестирование), использует разрешения по умолчанию (для доступа к файлам, сети требуется явное разрешение). Работает на V8.

- **Bun** — высокопроизводительный JavaScript Runtime нового поколения, написанный на Zig. Отличается быстрым запуском, встроенным сборщиком (bundle), поддержкой TypeScript и JSX из коробки. Работает на JavaScriptCore.

Несмотря на различия, все они постепенно сближаются благодаря развитию общих Web API и инициативам WinterTC (Web-interoperable Runtimes Community Group). WinterTC стандартизирует общие интерфейсы (Fetch, URL, Streams, AbortController, Web Crypto), доступные во всех средах.

Это означает, что всё больше кода можно переносить между различными средами практически без изменений. Например, функция, использующая Fetch API для HTTP-запросов, будет работать одинаково в браузере, Node.js, Deno и Bun.

## 1.6. Что изменилось за последние годы

Современный JavaScript значительно отличается от языка десятилетней давности. Ключевые тенденции развития можно свести к нескольким направлениям:

- **Развитие стандартной библиотеки** — появились `Map`, `Set`, `WeakMap`, `WeakSet`, `Promise`, `Symbol`, `BigInt`, `Temporal` (заменяет `Date`), `Iterator Helpers`. Это сокращает необходимость в сторонних библиотеках.

- **Отказ от устаревших подходов** — `var` заменён на `let` и `const`, callbacks — на Promises и `async/await`, CommonJS — на ES Modules.

- **Распространение нативных Web API** — Fetch, Streams, Web Workers, Web Crypto, WebGPU стали доступны во всех браузерах и серверных средах.

- **Переход на ES Modules** — модули стали стандартным способом организации кода, заменив CommonJS в браузерах и постепенно вытесняя его на сервере.

- **Постепенное исчезновение необходимости в тяжёлых полифилах** — современные браузеры поддерживают большинство новых возможностей напрямую.

- **Появление новых Runtime** — Deno и Bun предлагают альтернативы Node.js с улучшенной производительностью и безопасностью.

- **Развитие типизации через TypeScript** — TypeScript стал стандартом для крупных проектов, его поддержка встроена во многие инструменты и IDE.

- **Тесная интеграция JavaScript с Web Platform** — язык и платформа развиваются вместе, новые API появляются одновременно с новыми возможностями языка.

Главной особенностью JavaScript 2026 года является не одна конкретная языковая возможность, а зрелость всей экосистемы — языка, платформы, инструментов и практик разработки.

## 1.7. Для кого эта книга

Эта книга рассчитана на разработчиков, уже знакомых с основами JavaScript и желающих изучить современный язык таким, каким он используется в реальных проектах 2026 года.

Основное внимание уделяется:

- **Современному ECMAScript** — синтаксис, типы данных, функции, классы, модули, асинхронное программирование.
- **Web Platform API** — DOM, Fetch, Streams, Web Workers, Web Crypto, Storage, URL, и другие API.
- **Асинхронному программированию** — Event Loop, Promises, async/await, потоки данных, отмена операций.
- **Модульной архитектуре** — ES Modules, граф зависимостей, динамический импорт, Import Maps.
- **Производительности** — Rendering Pipeline, оптимизация загрузки, управление памятью, многопоточность.
- **Новым возможностям языка** — предложения TC39, которые скоро станут частью стандарта.
- **Лучшим инженерным практикам** — современный стиль написания кода, работа с инструментами, архитектура приложений.

Исторические особенности рассматриваются только там, где они помогают понять современное устройство языка. Книга не является историческим обзором — она сфокусирована на том, как писать код сегодня и в ближайшем будущем.

Разработка уже давно вышла за рамки написания небольших браузерных скриптов: сегодня JavaScript используется для построения сложных распределённых приложений, работающих в браузерах, на серверах, в облаке и на настольных системах.
