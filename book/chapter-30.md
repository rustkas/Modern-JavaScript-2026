К 2026 году **JavaScript** окончательно закрепил за собой статус ключевой технологической основы для построения распределённых систем искусственного интеллекта. Язык преодолел исторические ограничения интерфейсного слоя, превратившись в высокопроизводительную среду исполнения нейросетевых моделей непосредственно на клиентских устройствах. ## 30.1. WebGPU: высокопроизводительные вычисления общего назначения

Абсолютным технологическим драйвером клиентского ИИ выступает **WebGPU** — низкоуровневый системный интерфейс, ставший полноценной заменой устаревшему WebGL. Предоставляя прямой и безопасный доступ к аппаратным возможностям графических процессоров, WebGPU открыл эру браузерных вычислений на вычислительных шейдерах (Compute Shaders).

**Что такое WebGPU:**

WebGPU — это API для выполнения высокопроизводительных вычислений на GPU из браузера. В отличие от WebGL, который был разработан для графики, WebGPU спроектирован для вычислений общего назначения (GPGPU) и обеспечивает:

- Прямой доступ к GPU через современные низкоуровневые API (Vulkan, Metal, Direct3D 12).
- Выполнение вычислительных шейдеров (compute shaders) — программ, работающих на GPU.
- Эффективное управление памятью между CPU и GPU.
- Поддержку многопоточности и асинхронных операций.

**Пример использования WebGPU для вычислений:**

```javascript
// Создание адаптера и устройства
const adapter = await navigator.gpu.requestAdapter();
const device = await adapter.requestDevice();

// Создание буферов для данных
const inputBuffer = device.createBuffer({
  size: 1024 * 4, // 1024 числа с плавающей точкой
  usage: GPUBufferUsage.STORAGE | GPUBufferUsage.COPY_DST
});

const outputBuffer = device.createBuffer({
  size: 1024 * 4,
  usage: GPUBufferUsage.STORAGE | GPUBufferUsage.COPY_SRC
});

// Создание вычислительного шейдера
const shaderModule = device.createShaderModule({
  code: `
    @group(0) @binding(0) var<storage, read> input: array<f32>;
    @group(0) @binding(1) var<storage, read_write> output: array<f32>;

    @compute @workgroup_size(64)
    fn main(@builtin(global_invocation_id) id: vec3<u32>) {
      let index = id.x;
      output[index] = input[index] * 2.0; // Удвоение значений
    }
  `
});

// Выполнение вычислений
const commandEncoder = device.createCommandEncoder();
const pass = commandEncoder.beginComputePass();
pass.setPipeline(pipeline);
pass.dispatchWorkgroups(16); // 16 * 64 = 1024 потоков
pass.end();
device.queue.submit([commandEncoder.finish()]);
```

**Ключевые возможности WebGPU для AI:**

- **Массированный параллелизм:** Архитектура API позволяет эффективно распараллеливать ресурсоёмкие матричные и тензорные операции, составляющие математический фундамент современных больших языковых моделей (LLM). Тысячи ядер GPU могут выполнять вычисления одновременно.

- **Интеллектуальная оркестрация памяти:** JavaScript-агент берёт на себя роль координатора, контролирующего перемещение весов и активаций между оперативной памятью (RAM) и выделенной видеопамятью (VRAM) с минимальными накладными расходами.

- **Асинхронные вычисления:** WebGPU работает асинхронно, не блокируя основной поток JavaScript, что позволяет выполнять тяжёлые вычисления в фоне без потери отзывчивости интерфейса.

**Статус WebGPU в 2026 году:**

Здесь важна точность дат, поскольку путь WebGPU к полной кросс-браузерности был длиннее и завершился значительно позже, чем можно было бы предположить. Chrome поддерживает WebGPU стабильно с версии 113 (2023 год), однако два оставшихся крупных движка добавили поддержку значительно позже: **Firefox 141** (для Windows) — в июле 2025 года, а **Safari 26.0** — в сентябре 2025 года (macOS Tahoe, iOS, iPadOS, visionOS). Именно после появления поддержки в Safari, **25 ноября 2025 года**, WebGPU официально достиг полной кросс-браузерной доступности — Google объявила об этом как о моменте, когда технология стала доступна «по умолчанию» во всех четырёх основных браузерах (Chrome, Edge, Firefox, Safari).

Таким образом, точный статус на момент написания книги:

- WebGPU получил статус **Baseline Newly Available в конце 2025 года** (а не в 2024, как иногда ошибочно указывают из-за раннего появления в Chrome) — конкретно с ноября 2025 года, когда была закрыта поддержка в последнем из основных браузеров.
- Поддерживается в Chrome, Edge, Firefox (Windows, с частичной поддержкой macOS Apple Silicon и продолжающейся работой над Linux/Android) и Safari.
- Полная поддержка на всех платформах (включая Linux и Android для Firefox) продолжает дорабатываться в течение 2026 года.

Эта деталь важна не только формально: приложения, ориентированные на широкую аудиторию, включая пользователей Safari и Firefox, могли полагаться на WebGPU без fallback-сценария только начиная с конца 2025 года — то есть совсем недавно на момент выхода этой книги.

## 30.2. WebNN API: аппаратное ускорение на уровне нейропроцессоров

Если WebGPU является универсальным инструментом параллельных вычислений, то специализированный **WebNN API (Web Neural Network)** спроектирован целенаправленно для эффективного выполнения графов машинного обучения.

**Что такое WebNN API:**

WebNN API — это низкоуровневый API для выполнения нейросетевых операций с использованием аппаратного ускорения. Он предоставляет интерфейс для запуска обученных нейронных сетей на специализированных чипах.

**Пример использования WebNN API:**

```javascript
// Создание контекста нейросети
const context = await navigator.ml.createContext();

// Построение графа вычислений
const builder = new MLGraphBuilder(context);

// Входные данные (тензор)
const input = builder.input('input', { dimensions: [1, 3, 224, 224] });

// Свёрточный слой
const conv = builder.conv2d(input, weights, { padding: 'same' });

// Функция активации (ReLU)
const relu = builder.relu(conv);

// Сборка графа
const graph = await builder.build({ output: relu });

// Выполнение
const result = await context.compute(graph, { input: inputData });
```

**Ключевые возможности WebNN API:**

- **Интеграция с NPU:** Интерфейс задействует специализированные нейроморфные сопроцессоры (Neural Processing Units), встроенные в аппаратную базу устройств 2026 года, обеспечивая пиковую энергоэффективность. NPU потребляют значительно меньше энергии, чем GPU, при выполнении нейросетевых операций.

- **Нативная оптимизация примитивов:** Операции свёртки, нормализации, пуллинга, матричного умножения и активации выполняются на аппаратном уровне, демонстрируя кратное превосходство в скорости над чистыми программными реализациями на JavaScript.

- **Платформенная универсальность:** Будучи частью консорциумных стандартов Web Platform, WebNN гарантирует переносимость квантованных моделей между разнородными кремниевыми архитектурами.

**Основные операции WebNN API:**

- `conv2d`, `conv3d` — свёрточные слои.
- `averagePool2d`, `maxPool2d` — слои пуллинга.
- `matmul` — умножение матриц.
- `relu`, `sigmoid`, `tanh` — функции активации.
- `batchNorm` — пакетная нормализация.
- `lstm`, `gru` — рекуррентные слои.
- `softmax`, `reduceSum`, `concat` — вспомогательные операции.

**Статус WebNN API в 2026 году:**

Здесь необходимо исправить неточность в самой природе стандарта. WebNN — это **не предложение WHATWG**, а спецификация, разрабатываемая **W3C** в рамках Web Machine Learning Working Group. В январе 2026 года спецификация достигла статуса **Candidate Recommendation** — это значительно более зрелая стадия W3C-процесса, чем черновик, однако сама по себе она не означает готовности к продакшену: активная работа продолжается, в частности над сценариями использования для генеративного ИИ.

Практический статус поддержки в браузерах на момент написания книги значительно отстаёт от статуса спецификации:

- WebNN реализован **только в Chromium-браузерах** (Chrome, Edge), причём для широкой аудитории доступен лишь через Origin Trial (в частности, Chrome 147–149), а не как стабильная, включённая по умолчанию возможность.
- Полная поддержка GPU- и NPU-исполнения (не только CPU-бэкенда) всё ещё ограничена и в некоторых случаях требует специфичных условий — например, для execution provider на базе ONNX Runtime под Windows требуется Windows 11 24H2+ и явное включение флага.
- Firefox и Safari поддержки не реализовали.
- По оценкам сторонних наблюдателей, реалистичный срок, когда WebNN станет путём по умолчанию для продакшен-приложений — **не ранее 2027 года**.

Иными словами, на 2026 год рабочим стеком для инференса в браузере остаётся связка **WebGPU + Transformers.js/ONNX Runtime Web**, а не WebNN — несмотря на то, что WebNN предлагает потенциально более высокую энергоэффективность за счёт прямого доступа к NPU.

**Сравнение WebGPU и WebNN API:**

| Характеристика | WebGPU | WebNN API |
| -------------- | ------ | --------- |
| Основное назначение | Универсальные вычисления на GPU | Специализированные нейросетевые вычисления |
| Аппаратное ускорение | GPU (игровые и профессиональные) | NPU, GPU, CPU |
| Энергоэффективность | Средняя | Высокая (на NPU) |
| Гибкость | Высокая (полный контроль над шейдерами) | Ограниченная (только нейросетевые операции) |
| Простота использования | Сложная (требует написания шейдеров) | Относительно простая (граф вычислений) |
| Поддержка в 2026 | Baseline Newly available | Экспериментальная |

## 30.3. Инструментарий экосистемы: ONNX Runtime Web и Transformers.js

Инженерная сложность низкоуровневых API скрыта под высокоуровневыми библиотечными абстракциями, ставшими де-факто стандартом разработки в 2026 году.

**ONNX Runtime Web:**

Мощный движок, позволяющий разворачивать модели, обученные в фреймворках общего назначения (PyTorch, TensorFlow), прямо в среде браузера с гибридным использованием WebGPU, WebNN и WebAssembly.

```javascript
// Загрузка и выполнение ONNX-модели
import { InferenceSession, Tensor } from 'onnxruntime-web';

// Загрузка модели
const session = await InferenceSession.create('model.onnx');

// Подготовка входных данных
const inputTensor = new Tensor('float32', float32Array, [1, 3, 224, 224]);

// Выполнение инференса
const results = await session.run({ input: inputTensor });

// Получение результата
const output = results.output.data;
```

**Особенности ONNX Runtime Web:**

- Поддерживает ONNX (Open Neural Network Exchange) — открытый формат обмена моделями.
- Автоматически выбирает оптимальный бэкенд: WebGPU → WebNN → WebAssembly → CPU.
- Работает как в браузере, так и в Node.js/Deno/Bun.
- Поддерживает квантование (INT8, FP16) для уменьшения размера моделей.

**Transformers.js:**

Библиотека, перенесшая экосистему Hugging Face в браузерный мир. Позволяет разработчикам в несколько строк кода интегрировать передовые предобученные модели для обработки естественного языка (NLP), компьютерного зрения и распознавания речи.

```javascript
// Пример с Transformers.js
import { pipeline } from '@xenova/transformers';

// Создание пайплайна для генерации текста
const generator = await pipeline('text-generation', 'gpt2');

// Генерация текста
const result = await generator('The future of JavaScript is', {
  max_new_tokens: 50,
  temperature: 0.9
});

console.log(result[0].generated_text);
```

**Возможности Transformers.js:**

- Поддерживает сотни предобученных моделей из Hugging Face Hub.
- Работает с задачами: текстовые генерации, классификация, суммаризация, перевод, вопросы-ответы, распознавание речи, генерация изображений.
- Использует ONNX Runtime Web как бэкенд для выполнения.
- Поддерживает квантованные версии моделей (например, `gpt2` в 6 раз меньше оригинала).

**Архитектурная схема интеграции:**

```

│  │               (High-level abstraction)               │  │

│                │                   │                       │
```

## 30.4. Парадигма Local AI: безопасность, автономность и экономика

Повсеместный переход к обработке данных на стороне клиента продиктован прагматичными требованиями современной архитектуры.

**Абсолютная конфиденциальность:**

Обработка конфиденциального пользовательского текста, графики и биометрии локально на устройстве исключает риски утечек на этапе передачи данных по сети.

```
Клиентская модель:
Пользователь → (локальная обработка) → результат
(Данные не покидают устройство)

Облачная модель:
Пользователь → (передача по сети) → облачный сервер → обработка → результат → (возврат)
(Данные передаются по сети и хранятся на сервере)
```

**Пример локальной обработки конфиденциальных данных:**

```javascript
// Локальный AI-агент на устройстве
import { pipeline } from '@xenova/transformers';

// Загрузка модели для анализа текста (без отправки данных на сервер)
const classifier = await pipeline('sentiment-analysis');

// Обработка конфиденциального текста на устройстве
const text = 'Мой пароль: ***** и данные карты: ****';
const result = await classifier(text);
// Результат вычислен локально, данные не покинули устройство
```

**Оптимизация инфраструктурных затрат:**

Использование локальных вычислительных мощностей позволяет крупным компаниям разгружать облачные кластеры, существенно сокращая операционные расходы на инференс моделей.

| Подход | Инфраструктурные затраты | Задержка | Конфиденциальность |
| ------ | ------------------------ | -------- | ------------------ |
| Облачный AI | Высокие (аренда GPU) | Высокая (сеть) | Ограниченная |
| Локальный AI | Минимальные (клиентские устройства) | Нулевая (локально) | Полная |

**Офлайн-автономность:**

Благодаря интеграции с фоновыми процессами (Service Workers) и персистентными хранилищами (Cache API, IndexedDB), интеллектуальные функции продолжают функционировать в условиях полного отсутствия интернет-соединения.

```javascript
// Сохранение модели в кеше для офлайн-режима
const cache = await caches.open('ai-models');
await cache.add('/models/sentiment-model.onnx');

// Загрузка модели из кеша при отсутствии сети
const response = await cache.match('/models/sentiment-model.onnx');
const modelBuffer = await response.arrayBuffer();
```

## 30.5. Архитектурная роль JavaScript в AI

В парадигме **Local AI** JavaScript выполняет роль оркестратора:

1. **Загрузка моделей** — через Fetch API из CDN или Cache API из кеша.
2. **Оркестрация вычислений** — выбор оптимального бэкенда (WebGPU, WebNN, WebAssembly).
3. **Управление памятью** — контроль перемещения данных между RAM и VRAM.
4. **Обработка потоков** — использование Streams API для обработки больших моделей по частям.
5. **Интеграция с UI** — обновление интерфейса через DOM, реактивные системы.
6. **Работа с Service Workers** — фоновые вычисления, офлайн-режим.

**Пример полного пайплайна:**

```javascript
// 1. Загрузка модели через Fetch
const modelResponse = await fetch('/models/llm.onnx');
const modelBuffer = await modelResponse.arrayBuffer();

// 2. Инициализация движка (ONNX Runtime)
const session = await InferenceSession.create(modelBuffer);

// 3. Подготовка данных
const inputTensor = new Tensor('float32', inputData, [1, sequenceLength]);

// 4. Выполнение вычислений (на WebGPU/WebNN)
const results = await session.run({ input: inputTensor });

// 5. Обработка результата
const output = results.output.data;

// 6. Обновление UI
document.getElementById('result').textContent = output;
```

## Заключение

В ландшафте 2026 года владение инструментами интеграции ИИ в JavaScript — это обязательная компетенция для эффективной оркестрации потоков данных между аппаратными API платформы и оптимизированными клиентскими рантаймами.

**WebGPU** предоставляет доступ к GPU для высокопроизводительных параллельных вычислений, выполняя вычислительные шейдеры и эффективно управляя памятью между CPU и GPU. **WebNN API** обеспечивает аппаратное ускорение нейросетевых операций на специализированных NPU, с нативной оптимизацией примитивов свёртки, пуллинга, матричного умножения.

**ONNX Runtime Web** и **Transformers.js** являются высокоуровневыми абстракциями, скрывающими сложность низкоуровневых API. ONNX Runtime Web позволяет запускать модели в формате ONNX с гибридным использованием WebGPU, WebNN и WebAssembly. Transformers.js предоставляет доступ к сотням предобученных моделей из Hugging Face Hub.

Парадигма **Local AI** обеспечивает конфиденциальность данных (обработка на устройстве без передачи в облако), сокращение инфраструктурных затрат (локальное выполнение вместо облачных GPU) и офлайн-автономность (через Service Workers и Cache API).

Синергия передовых языковых возможностей и стандартов **Baseline** превратила браузер в полноценную интеллектуальную операционную среду, где JavaScript выступает координатором между аппаратными возможностями устройства и интеллектуальными алгоритмами.
