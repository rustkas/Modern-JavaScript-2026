# Часть I. JavaScript в 2026 году

# Глава 1. Современный JavaScript: язык Web Platform

JavaScript 2026 года — это значительно больше, чем очередная версия ECMAScript. Сегодня разработчик работает одновременно с языком, стандартной библиотекой, Web API, современными средами выполнения и инструментами разработки. Именно их сочетание образует современную платформу JavaScript.

Эта глава знакомит с общей архитектурой экосистемы, которая станет фундаментом для всех последующих разделов книги.

---

## 1.1. Из чего состоит современный JavaScript

Современный JavaScript — это несколько взаимосвязанных уровней.

**Язык (ECMAScript)** — определяет синтаксис и семантику языка: типы данных (`string`, `number`, `object`, `symbol`), функции, классы, модули, асинхронное программирование (`Promise`, `async/await`), стандартную библиотеку (`Array`, `Map`, `Set`, `Date`). Именно этому посвящена значительная часть книги.

**Web Platform API** — предоставляет тысячи стандартных интерфейсов для работы с веб-платформой:

- **DOM** — управление структурой HTML-документа.
- **Fetch** — выполнение сетевых запросов.
- **Streams** — потоковая обработка данных.
- **Web Storage** — хранение данных в браузере (`localStorage`, `sessionStorage`).
- **URL** — парсинг и конструирование URL-адресов.
- **Encoding** — преобразование между текстовыми кодировками.
- **Clipboard** — работа с буфером обмена.
- **Web Workers** — многопоточность в браузере.
- **Web Crypto** — криптографические операции.
- **Canvas** — 2D-графика.
- **File API** — работа с файлами.
- **Web Components** — создание кастомных элементов.
- **WebSocket** — двунаправленная связь с сервером.
- **WebRTC** — реальное время, видео и аудио.
- **WebGPU** — высокопроизводительная 3D-графика.

Язык становится полезным именно благодаря этим API. Без них JavaScript был бы просто абстрактным языком программирования — с ними он становится полноценной платформой для создания приложений. Сегодня разработчик изучает не только язык, но и платформу, поскольку именно API определяют, что можно сделать в браузере или серверной среде.

**Runtime (среда выполнения)** — обеспечивает выполнение JavaScript в конкретной среде. Существует множество сред:

- **Browser** — браузеры (Chrome, Firefox, Safari, Edge), предоставляют DOM, Fetch, Web Workers и другие клиентские API.
- **Node.js** — серверная среда на основе V8, предоставляет файловую систему, HTTP-сервер, криптографию, процессы.
- **Deno** — современная среда выполнения от создателя Node.js, с поддержкой TypeScript из коробки и безопасностью по умолчанию.
- **Bun** — высокопроизводительная среда выполнения, написанная на Zig, с быстрым запуском и встроенным сборщиком.
- **Cloud Runtime** — облачные среды (AWS Lambda, Google Cloud Functions, Azure Functions) для выполнения кода в ответ на события.
- **Edge Runtime** — выполнение на границе (Cloudflare Workers, Vercel Edge, Fastly Compute) с низкой задержкой.

Несмотря на различия, среды постепенно используют всё больше общих Web API. Например, Fetch и URL API доступны в браузере, Node.js, Deno и Bun. Это упрощает перенос кода между средами.

**Инструменты** — современная разработка невозможна без инструментария:

- **TypeScript** — статическая типизация, улучшает качество кода и опыт разработки.
- **ESLint** — статический анализ кода, поиск ошибок и нарушений стиля.
- **Prettier** — автоматическое форматирование кода.
- **Vite** — быстрый сборщик и сервер разработки с мгновенной горячей перезагрузкой (HMR).
- **Rollup** — сборщик для производства, оптимизирует бандлы.
- **esbuild** — сверхбыстрый сборщик на Go, используется как бэкенд в Vite и других инструментах.
- **npm / pnpm / yarn** — менеджеры пакетов для управления зависимостями.
- **Vitest** — быстрый тестовый фреймворк на основе Vite.

Инструментарий перестал быть "дополнением" к языку и стал частью повседневной инженерной практики. Без него современная разработка практически невозможна из-за сложности проектов.

## 1.2. ECMAScript развивается непрерывно

JavaScript больше не переживает революций наподобие ES6 (ECMAScript 2015). После 2015 года язык развивается небольшими ежегодными обновлениями, каждое из которых добавляет ограниченный набор возможностей.

Каждый новый стандарт включает только полностью завершённые предложения, уже прошедшие длительное тестирование в реальных движках (Stage 4 в процессе TC39). Это означает, что новые возможности сначала реализуются в браузерах и рантаймах, а затем фиксируются в спецификации.

Благодаря этому язык остаётся стабильным, сохраняя обратную совместимость. Новые возможности не ломают существующий код, что позволяет крупным проектам обновляться постепенно.

Для разработчика важнее понимать направление развития языка (какие концепции внедряются, какие паттерны становятся стандартными), чем запоминать номера редакций стандарта. Гораздо полезнее знать, что язык движется в сторону большей выразительности, безопасности и производительности, чем помнить, какая именно версия добавила ту или иную конструкцию.

## 1.3. Как появляются новые возможности

Развитием языка занимается комитет TC39 (Technical Committee 39) — группа, состоящая из представителей компаний-разработчиков браузеров (Google, Apple, Mozilla), а также независимых экспертов.

Каждое предложение проходит несколько стадий, прежде чем стать частью стандарта:

- **Stage 0 (Strawman)** — идея, представленная для обсуждения. На этом этапе нет спецификации, просто описание проблемы и возможного решения.
- **Stage 1 (Proposal)** — формальное предложение. Комитет рассматривает идею и решает, стоит ли её развивать. На этом этапе появляется черновик спецификации.
- **Stage 2 (Draft)** — проект спецификации. Предложение имеет формальное описание на языке ECMAScript. Начинается реализация экспериментальных версий в движках.
- **Stage 3 (Candidate)** — готовность к реализации. Спецификация завершена, ожидаются отзывы от реализаторов (браузеров, Node.js). На этом этапе изменения возможны только для исправления критических проблем.
- **Stage 4 (Finished)** — включение в стандарт. Предложение реализовано в как минимум двух независимых движках и прошло тестирование. На следующем ежегодном обновлении ECMAScript оно становится частью официального стандарта.

Практически все новые возможности появляются в браузерах ещё до официального выхода очередной редакции ECMAScript. Например, Top-Level Await был доступен в браузерах задолго до его включения в стандарт ES2022. Именно поэтому современная разработка всё чаще ориентируется не на номер стандарта, а на фактическую поддержку движками — проверяя, работает ли возможность в целевых средах, а не соответствует ли код конкретной версии ECMAScript.

## 1.4. Living Standard и Baseline

JavaScript развивается как живой стандарт (Living Standard) — это означает, что спецификация постоянно обновляется, а не выпускается раз в несколько лет большими версиями. Браузеры внедряют новые возможности практически непрерывно, по мере их готовности.

Вместо проверки *"Поддерживает ли браузер ES2026?"*, современный разработчик задаёт вопрос: *"Доступна ли эта возможность в Baseline?"*

**Модель Baseline** — это подход, предложенный Google, Mozilla и другими участниками Web Platform, для оценки готовности технологии к промышленному использованию.

**Как работает Baseline:**

- Технология попадает в **Baseline Newly Available**, когда она поддерживается во всех основных браузерах (Chrome, Firefox, Safari, Edge) в их текущих стабильных версиях.
- Технология попадает в **Baseline Widely Available**, когда она доступна в браузерах как минимум 30 месяцев (2.5 года). Это означает, что подавляющее большинство пользователей уже используют браузеры с поддержкой этой технологии.

Baseline не заменяет проверку совместимости, но упрощает принятие решений. Если технология в Baseline Widely Available, её можно использовать без полифилов практически в любом проекте. Если в Baseline Newly Available — можно использовать с осторожностью, оценивая аудиторию. Если технология ещё не в Baseline — следует использовать полифилы или воздержаться от использования в продакшене.

Baseline позволяет оценивать готовность технологии к промышленному использованию независимо от номера версии языка, что делает её удобным инструментом для принятия инженерных решений.

## 1.5. Конец эпохи транспиляции "по умолчанию"

Ещё несколько лет назад практически любой проект автоматически проходил через Babel — транспилятор, преобразующий современный JavaScript в код, понятный старым браузерам. Это было необходимо, чтобы использовать новые возможности языка, не дожидаясь их поддержки во всех браузерах.

В 2026 году ситуация изменилась. Большинство современных браузеров поддерживает:

- **ES Modules** — нативная модульная система, работающая во всех современных браузерах без транспиляции.
- **async/await** — стандартный способ работы с асинхронным кодом.
- **Private fields** — приватные поля классов (`#field`).
- **Top-level await** — использование `await` на верхнем уровне модулей.
- **Import attributes** — атрибуты для импорта (например, `import data from './data.json' with { type: 'json' }`).
- **Современные возможности ECMAScript** — такие как `Array.prototype.toSorted()`, `Object.groupBy()`, `Promise.withResolvers()` и другие.

Во многих проектах необходимость в транспиляции исчезла или значительно сократилась. Разработчики могут писать современный JavaScript и запускать его напрямую в браузере или Node.js, без этапа преобразования.

Транспиляция всё чаще используется для оптимизации сборки, а не для совместимости. Например, TypeScript транспилируется в JavaScript для удаления типов, но сам JavaScript остаётся современным. Babel может использоваться для минификации и оптимизации кода, а не для преобразования синтаксиса. Сборщики (Vite, Rollup, esbuild) обрабатывают модули, но не изменяют синтаксис языка.

Это снижает сложность сборки, ускоряет время разработки и упрощает отладку, поскольку разработчик видит в браузере тот же код, который написал.

## 1.6. JavaScript как единая платформа

Главная тенденция последних лет — сближение различных сред выполнения. Browser, Node.js, Deno и Bun постепенно используют одинаковые API, что делает JavaScript действительно единой платформой.

**Общие API, доступные во всех основных средах:**

- **Fetch** — выполнение HTTP-запросов.
- **URL** — парсинг и конструирование URL.
- **Streams** — работа с потоками данных.
- **Blob** — работа с бинарными данными.
- **TextEncoder / TextDecoder** — преобразование между текстом и байтами.
- **AbortController** — отмена асинхронных операций.
- **Web Crypto** — криптографические операции.
- **EventTarget** — событийная модель.

**Инициатива WinterTC** играет большую роль в этом процессе, но важно точно понимать её текущий организационный статус. Изначально работа велась в рамках открытой рабочей группы W3C — **WinterCG** (Web-interoperable Runtimes Community Group), объединявшей разработчиков разных сред выполнения (браузеры, Node.js, Deno, Bun, Cloudflare Workers). Однако в январе 2025 года WinterCG была закрыта, а её работа передана в **Ecma International** — ту же организацию, которая через TC39 стандартизирует сам язык. Новая структура получила официальное название **Ecma TC55**, сохранив за собой узнаваемое имя **WinterTC** (Technical Committee on Web-interoperable Server Runtimes). Это переход от статуса сообщества к полноценному техническому комитету, обладающему полномочиями публиковать стандарты, — важный шаг к формализации инициативы.

WinterTC определяет «минимальный общий API» (minimum common API) — набор Web-интерфейсов, которые должны быть доступны в любой среде выполнения JavaScript. Это делает перенос кода между различными Runtime значительно проще. Разработчик может написать код, использующий Fetch API, и он будет работать в браузере, Node.js, Deno, Bun и Cloudflare Workers без изменений.

Современный JavaScript всё меньше зависит от конкретной среды выполнения — он становится универсальным языком для всего спектра приложений: от клиентских интерфейсов до серверных микросервисов и edge-вычислений.

## 1.7. Что изменилось за последнее десятилетие

Эволюцию языка можно свести к нескольким ключевым тенденциям, которые сформировали современный JavaScript:

- **Ежегодные обновления вместо крупных революций** — после ES6 язык развивается постепенно, без ломающих изменений.
- **Переход на ES Modules** — модули стали стандартным способом организации кода, заменив CommonJS в браузерах и постепенно вытесняя его на сервере.
- **Развитие стандартной библиотеки** — появились `Map`, `Set`, `WeakMap`, `WeakSet`, `Promise`, `Symbol`, `BigInt`, **`Iterator Helpers`** (часть **ES2025**, статус Baseline Newly Available с марта 2025 года). Отдельно стоит упомянуть **`Temporal`** — новый API для дат и времени, призванный со временем заменить `Date`: он достиг Stage 4 и вошёл в стандарт **ES2026** (март 2026 года), уже работает нативно в Chrome 144+, Firefox 139+ и Edge 144+, но на момент написания книги ещё не поддерживается Safari, из-за чего формально не имеет статуса Baseline. Стоит закладывать полифил там, где важна поддержка Safari.
- **Распространение Web API** — тысячи API стали доступны во всех браузерах: Fetch, Streams, Web Workers, Web Crypto, WebGPU.
- **Отказ от устаревших браузеров** — поддержка Internet Explorer прекращена, современные браузеры обновляются автоматически.
- **Появление современных Runtime** — Deno и Bun предлагают альтернативы Node.js с улучшенной производительностью и безопасностью.
- **Интеграция TypeScript в экосистему** — TypeScript стал стандартом для крупных проектов, его поддержка встроена во многие инструменты и IDE.
- **Уменьшение роли транспиляции** — современные браузеры поддерживают большинство новых возможностей напрямую, хотя отдельные знаковые технологии (как Temporal) всё ещё проходят переходный период и требуют проверки статуса Baseline перед использованием без полифилов.
- **Унификация серверной и клиентской разработки** — одни и те же API (Fetch, Streams, Crypto) доступны везде.

Именно эти изменения сформировали JavaScript образца 2026 года — зрелый, стабильный язык с богатой экосистемой, единой моделью выполнения и широкими возможностями для разработки любых типов приложений.

## Заключение главы

Современный JavaScript представляет собой не отдельный язык программирования, а полноценную программную платформу. Язык ECMAScript, Web API, современные Runtime и инструменты разработки образуют единую экосистему, в которой создаётся большинство веб-приложений. ECMAScript определяет синтаксис и базовые структуры. Web Platform API предоставляет интерфейсы для работы с сетью, графикой, файлами, криптографией. Runtime обеспечивают выполнение в разных средах — браузере, сервере, edge-сетях. Инструменты (TypeScript, сборщики, линтеры) автоматизируют разработку и повышают качество кода. Все эти уровни вместе образуют платформу, на которой строятся современные приложения.

Следующие главы книги посвящены каждому из этих аспектов: мы начнём с архитектуры рантайма и того, как JavaScript выполняется в браузере и на сервере, затем перейдём к современным возможностям ECMAScript, модульной системе, асинхронному программированию, Web API и инженерным практикам, определяющим разработку на JavaScript в 2026 году.
